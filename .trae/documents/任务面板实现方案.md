# 任务面板实现方案

## 1. 摘要

在 `lobby.html` 的冒险日记（`data-panel="adventure"`）内新增一个整体任务面板。玩家点击“当前任务”面板右上角的“查看全部任务 →”后，从剧本详情页切换到任务面板。任务面板采用左右两栏布局：左侧为任务分类导航（主线任务 / 地区名 / 已完成任务），右侧展示选中任务的概览详情。支持主线任务展开查看阶段小任务，并自动将已完全完成的任务归入“已完成任务”。

## 2. 当前状态分析

- 冒险日记面板位于 `lobby.html:1949-2241`，内部通过 `campaign-select`（剧本书架）与 `campaign-detail`（剧本详情）切换。
- 剧本详情页已包含“当前任务”概览面板（`.panel` + `.task-list`），右上角有“查看全部任务 →”入口（`lobby.html:2052`），但当前无交互。
- 面板切换使用 `switchPanel()`（`lobby.html:2839-2846`）与 `campaignSelect / campaignDetail` 显隐控制（`lobby.html:2884-2904`）。
- 现有的特性展开交互（`lobby.html:2875-2881`）使用 `expanded` 类 + `feature-detail` 元素，可作为子任务展开的参考模式。
- 样式层使用 CSS 变量（`--ink`、`--paper-card`、`--accent` 等）统一主题，新面板应继续沿用。

### 3.2 左侧任务导航

- 仅保留三类：**主线任务**、**地区名**、**已完成任务**。移除参考图中的“普通任务”。
- 每个分类标题右侧显示该分类下的任务数量，例如 `主线任务(Main Quest) (1)`。
- 导航项默认显示任务名称 + 状态标签（进行中 / 已完成）。
- 当前选中项高亮显示，使用 `active` 类。
- 已完成任务的任务名称使用删除线或置灰样式（`task-completed` 类）。

### 3.3 右侧任务详情

- 顶部不显示地点标识（如参考图中的“巴洛维亚”小字标签）。
- 标题下方显示状态标签（进行中 / 已完成）和日期。
- 对于主线任务，显示“阶段目标”区域，阶段目标以可展开列表呈现：
  - 第一阶段“遭遇神秘存在”标记为已完成，文字旁显示“（已完成）”。
  - 第二阶段“寻找第一块暗金色碎片”未标记完成。
  - 每个阶段右侧提供展开图标（两条边的空心三角），点击后展开该阶段的详细描述。
- 阶段目标下方是任务整体概述文本，不记录特别详细的任务需求，仅用于快速浏览。

### 3.4 子任务展开交互

- 参考现有 `.feature-list li` 与 `.feature-detail` 的相邻兄弟选择器模式。
- 为 `.subtask` 行绑定点击事件，切换 `expanded` 类。
- `.subtask-detail` 默认 `display: none`；当 `.subtask.expanded + .subtask-detail` 时显示，并添加过渡动画。
- 展开图标使用空心 V 形（两条边），展开时旋转 180°。

### 3.5 任务完成与自动归类逻辑

- 在任务数据中，每个任务对象包含 `completed: boolean` 与 `subtasks: [{ text, completed, detail }]`。
- 初始化渲染时：
  - 若任务 `completed === true`，放入“已完成任务”分类。
  - 若存在任一未完成的 `subtask` 或任务本身未完成，放入对应主线任务或地区名分类。
- 当某个任务的所有 `subtasks` 都变为 `completed === true` 时，自动将该任务标记为已完成并移入“已完成任务”分类，重新渲染左侧导航。
- 当前任务面板首页的“当前任务”列表保持不变，仅作为入口展示。

### 3.6 新增 CSS 样式

文件：`/home/zyh/DND/lobby.html`（`<style>` 内追加）

需要新增以下样式类：

- `.task-board`：任务面板容器，默认隐藏，与 `.campaign-detail` 内部结构同宽。
- `.task-columns`：两栏网格，`grid-template-columns: 320px 1fr`。
- `.task-sidebar`：左侧分类导航卡片。
- `.task-category`：分类组。
- `.task-category-title`：分类标题，带计数。
- `.task-nav-item`：单个导航项，hover / active 态。
- `.task-nav-item.task-completed`：已完成任务的置灰/删除线样式。
- `.task-nav-status`：状态小标签。
- `.task-detail`：右侧详情卡片。
- `.task-detail-header`：详情头部，含状态标签、标题、日期。
- `.task-detail-tag`：状态胶囊标签。
- `.task-section-title`：“阶段目标”小标题。
- `.subtask`：阶段目标行，可点击。
- `.subtask.completed`：已完成阶段的样式，勾选图标为实心/已填充。
- `.subtask-check`：复选框图标容器。
- `.subtask-expand`：空心三角展开图标容器。
- `.subtask-detail`：阶段详情，默认隐藏。

颜色继续沿用 CSS 变量，例如：
- 进行中标签使用 `--accent` 背景 + 白色文字。
- 已完成标签使用灰绿色或 `--ink-soft` 降低透明度。
- 已完成任务文字使用 `--ink-soft` 并加 `text-decoration: line-through`。

### 3.7 新增 / 调整 JavaScript

文件：`/home/zyh/DND/lobby.html`（`<script>` 区域追加）

1. **数据定义**：在脚本顶部定义任务数据常量：
   ```javascript
   const quests = [
     {
       id: 'dark-gold',
       category: 'main',
       title: '暗金碎片的契约',
       status: '进行中',
       date: '2025/1/23',
       completed: false,
       description: '我们失去了部分属性和装备，作为交换，必须为他收集一种封存着黑暗阴影和时间法则的“暗金色碎片”。寻找这些碎片，否则我们的存在可能会消散。',
       subtasks: [
         { text: '遭遇神秘存在', completed: true, detail: '在碾骨老磨坊被夜鬼婆杀害后，一个坐在断手王座上的神秘存在复活了我们。' },
         { text: '寻找第一块暗金色碎片', completed: false, detail: '详细描述待补充。' }
       ]
     },
     // 其余任务占位数据
   ];
   ```

2. **渲染函数**：
   - `renderTaskSidebar()`：按分类渲染左侧导航，自动区分已完成与进行中。
   - `renderTaskDetail(questId)`：渲染右侧详情，绑定子任务展开事件。
   - `checkQuestCompletion(quest)`：遍历 `subtasks`，若全部完成则置 `completed = true` 并重新渲染。

3. **事件绑定**：
   - “查看全部任务 →”点击 → 隐藏原内容、显示 `#task-board`，默认选中第一个主线任务。
   - “返回剧本详情”点击 → 隐藏 `#task-board`，恢复显示原内容。
   - 左侧 `.task-nav-item` 点击 → 切换 active 态并渲染右侧详情。
   - 右侧 `.subtask` 点击 → 切换 `expanded` 类展开详情。

4. **状态自动迁移**：
   - 提供 `toggleSubtask(questId, index)` 函数供后续交互调用，内部调用 `checkQuestCompletion()`，若任务完成则自动移入“已完成任务”并刷新侧边栏。
   - 当前实现中通过静态数据展示自动迁移效果，可手动将示例数据中的 `subtasks` 全部置为 `completed: true` 验证样式变化。

## 4. 假设与决策

- **单 HTML 方案**：继续沿用项目当前策略，所有新 UI 写入 `lobby.html`，不新建文件。
- **不改动服务器/后端**：任务完成状态由前端静态数据管理；后续若需持久化，再接入数据存储。
- **参考图差异**：
  - 去掉任务标题上方的地点标识。
  - 去掉“普通任务”分类。
  - 主线任务的阶段目标可展开，第一阶段显示“（已完成）”。
  - 新增“已完成任务”分类，完成的任务自动归入此处。
- **地区名分类**：暂时使用“巴洛维亚”作为示例地区名，后续可随实际任务数据扩展。
- **子任务详情内容**：按用户要求先留占位文本，仅实现展开功能。
