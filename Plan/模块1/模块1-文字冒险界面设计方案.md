# 模块1：文字冒险界面设计方案

**文档版本**：v2.8
**编写日期**：2026-07-27
**更新日期**：2026-08-14（引擎播报人称统一：GM 叙述全用角色名；通缉直接播报 + 越狱重罪通缉全城（`wanted_location` 改地点 id 列表）；对峙/搜身/卫兵结算附赃物价值构成（防 AI 编造单价）；人称约束提升为第一层铁律 + 通缉状态注入 AI 上下文【通缉】；技能检定接入角色卡熟练加值（`skill_bonus`，角色卡 value 为权威））
**所属模块**：模块1 - 前端多端交互与沉浸式界面模块

---

## 1. 概述

### 1.1 设计目标

为 DNDBOX 的非战斗阶段提供贴合线下跑团体验的交互界面。玩家通过自由文本输入宣告动作，由 AI GM 或真人 GM 根据当前剧本章节、地点状态和角色能力进行裁定与叙事推进。

界面核心不再是「空间网格探索」，而是：

> **GM 描述场景 → 玩家自由输入动作 → 系统/AI 裁定并更新世界状态 → 叙事日志追加结果**

### 1.2 核心设计理念

| 要素 | 设计 |
|------|------|
| **叙事** | 中央为可滚动叙事日志，按时间顺序展示 GM 描述、玩家动作、检定结果、NPC 对话 |
| **输入** | 日志下方为自由文本输入框，玩家输入想说或想做的事 |
| **上下文** | 左侧面板展示当前地点的可见 NPC、物品、出口；点击可查看详细描述 |
| **角色** | 右侧面板展示完整角色卡，含属性、技能、背包、法术 |
| **数据** | 全 JSON 驱动，剧本分章节，AI/规则引擎只读取当前章节相关数据 |
| **约束** | AI GM 受硬规则约束，不能引入当前上下文之外的 NPC、地点、物品或剧情 |

### 1.3 页面定位

- 文件：`adventure.html`（独立页面）
- 复用 lobby.html 的色彩体系（CSS 变量）
- 从 lobby.html 点击"开始冒险"跳转进入，携带剧本 ID 与章节 ID 参数

### 2.1 顶部栏

- 左侧：返回大厅按钮
- 中央：DNDBOX 品牌

### 2.2 中央区域

中央区域是核心交互区，包含：

#### 2.2.1 地点标题

- 显示当前地点名称，如 `石丘旅馆 · 大厅`
- 若剧本有设定当前时间、天气或章节，可在标题下方以小字显示；无设定则不显示
- 进入新地点时自动更新

#### 2.2.2 叙事日志（narrative-log）

- 带垂直滚动条的文本区域
- 按时间顺序追加消息条目
- 每条消息标注角色/来源，如 `GM:`、`玩家:`、`系统:`
- 不添加 emoji，纯文字呈现
- 新消息自动滚动到底部
- 消息类型：
  - GM 场景描述
  - 玩家输入的动作
  - 检定请求与结果
  - NPC 对话
  - 被动技能触发提示
  - 状态变化提示（获得/失去物品、NPC 态度变化等）

#### 2.2.3 输入区

- 单行或少量行文本输入框
- 提示文字：`我想说/想做...`
- 发送按钮
- 支持回车发送
- 输入框上方不放固定快捷按钮（侦察/调查放到右侧面板角色卡附近）

### 2.3 左侧面板：当前场景上下文

左侧面板显示玩家角色当前能感知到的事物，定位为"你已注意到的事物"，不是可交互白名单。玩家仍可输入面板未列出动作。

#### 2.3.1 当前地点

- 地点名称
- 点击地点名称：弹出地点详细描述框

#### 2.3.2 人物

- 当前在场的 NPC 列表
- 每个 NPC 显示：名称 + 简短身份
- 点击 NPC：弹出描述框，显示完整介绍、当前状态、可见信息
- 描述框内可继续输入与该 NPC 相关的动作

#### 2.3.3 物品

- 当前地点中可见的物品列表
- 点击物品：弹出描述框，显示物品描述、主人（若有）、是否可拾取/偷窃

#### 2.3.4 出口

- 当前地点可通往的其他地点
- 点击出口：弹出描述框，显示出口描述，或自动在输入框填入移动动作草稿

#### 2.3.5 当前任务

- 从 quests.json 加载，仅显示 `status === 'active'` 的任务
- 点击任务展开子任务列表（仅显示已完成 + 第一个未完成，防剧透）
- 任务名右侧有展开按钮（SVG 向下箭头），点击展开/收起子任务，箭头旋转 180° 带 0.25s 过渡动画，样式与任务详情模态框左侧列表一致
- 展开/收起为局部 DOM 操作（切换 class + 插入/移除子任务行），避免整块重渲染导致动画失效
- 点击子任务弹出详情模态框（左侧分类 + 右侧阶段目标 + SVG 勾选框）
- 全部子任务完成后任务从侧边栏消失

### 2.4 右侧面板：完整角色卡

右侧面板展示完整角色信息：

- 头像、名称、种族、职业、等级
- 属性值（力量、敏捷、体质、智力、感知、魅力）
- 技能列表（可点击发起检定）
- 豁免检定
- HP / AC / 先攻 / 速度
- 背包
- 法术位和已知法术
- 经验值系统已移除（不做经验系统），角色卡底部不再显示 XP 经验条；武器栏中间显示 `Lv.xx` 等级徽章（从角色数据 `level` 字段读取）
- 角色名紧贴头像框上侧（不再独立占一行）

#### 2.4.1 侦察 / 调查快捷按钮

在角色卡附近放置两个常用检定按钮：

- **侦察**：触发感知（Perception）检定，查看周围环境
- **调查**：触发调查（Investigation）检定，仔细检查某个区域或物品

点击后系统自动发送对应动作并掷骰。

#### 2.4.2 装备系统（角色卡装备栏 + 背包交互）

- 角色卡左右两侧装备槽（头盔/护甲/盾牌/靴子 | 项链/戒指×2/工具），底部近战/远程武器槽（各 2 个并排）
- 已装备物品：槽位高亮 + 显示装备名 + 悬停 0.5s 显示详情（名称/属性/描述，与背包物资提示一致）
- 槽位图标动态关联：从装备 JSON 的 `icon` 字段加载 `/assets/icons/equipment/*.svg`；空槽显示默认槽图标，已装备槽显示物品自身图标（如装盾牌显示盾牌图标）
- 背包物品卡右键菜单：装备/卸下、丢弃、赠送（抄 lobby.html），装备/卸下不输出系统日志（丢弃/赠送保留提示）
- 属性跟随物品加值（D&D 5e 规则，详见 6.4）：
  - AC = 无甲 10+敏捷调整 → 取已装备护甲（轻甲+敏调 / 中甲+min(敏调,2) / 重甲）→ +盾牌 → +饰品加值（如防护戒指 +1）
  - 攻击加值 = 熟练加值 + 属性调整值（近战力量 / 远程敏捷）+ 武器加值
  - 伤害骰取自已装备武器（无武器回退 1d4）
- 武器可多件同时装备（取消同 category 武器互斥），武器槽按装备顺序填充（第 1 槽 / 第 2 槽）
- 装备/卸下/丢弃后自动重算属性并保存到角色 JSON（PUT /api/characters/{id}），lobby 与 adventure 共享同一份角色数据

### 2.5 拖拽把手

- 保留左/右面板的拖拽调整宽度
- 宽度持久化到 localStorage
- 恢复时保证中央区域最小宽度
- 三栏内部尺寸随面板宽度等比缩放：装备栏/物品格子随 `--right-panel-w`、左侧面板内容随 `--left-panel-w`（字号、高度、间距、圆角均为 `calc(面板宽 × 系数)`）

## 3. 交互模型

### 3.1 核心循环

```
GM 描述当前场景
    ↓
玩家阅读后在输入框输入动作
    ↓
后端意图识别（对玩家透明）
    ↓
规则引擎判断是否需要检定、目标是否合法
    ↓
后端自动掷骰
    ↓
AI GM / 真人 GM 根据结果生成叙事回复
    ↓
更新世界状态（物品、NPC、玩家状态）
    ↓
叙事日志追加结果
```

### 3.2 玩家输入示例

```
GM：石丘旅馆的大厅里壁炉噼啪作响。托布拉·石丘正在吧台后擦杯子，
    弗雷达·矿工坐在角落。吧台后面挂着一串客房钥匙。

玩家：我想趁托布拉不注意，偷走那把钥匙串。

系统：请进行巧手（Sleight of Hand）检定，难度 12。

[后端自动掷骰：d20 + 加值 = 14]

GM：你借着桌子的掩护，手指轻巧地勾住了钥匙串。托布拉仍在擦杯子，
    完全没有注意到。你获得了：客房钥匙串。
```

### 3.3 输入辅助

左侧面板的 NPC、物品、出口可点击，点击后弹出详细描述框。当前阶段不实现"点击后自动填充输入框"的快速选择功能，后续可扩展。

### 4.2 可见信息

- 地点描述、NPC、物品、出口默认对进入该地点的玩家可见
- 不单独设置"显眼物品"分类

### 4.3 隐藏信息

- 由 `hidden` 字段定义
- 需要玩家主动侦察/调查，或被动技能满足 DC 才能发现
- 剧本未写隐藏信息时，不硬加

### 4.4 场景节点

- 预置的触发式叙事片段
- 当玩家满足触发条件时，GM 叙事中自然插入
- 用于控制剧情节奏和关键信息释放

## 5. NPC 系统

### 5.1 NPC 数据

NPC 需要足够完整的设定，AI 才能保持一致发挥：

```jsonc
{
  "toblen-stonehill": {
    "id": "toblen-stonehill",
    "name": "托布拉·石丘",
    "race": "矮人",
    "role": "旅馆老板",
    "description": "一位面容和蔼的矮人旅馆老板...",
    "personality": ["谨慎", "好客", "护短"],
    "goals": ["保护旅馆和家人", "赚足够的钱"],
    "fears": ["红标帮", "失去旅馆"],
    "secrets": ["他其实藏了一把魔法匕首在吧台下面"],
    "passive_perception": 12,
    "passive_insight": 10,
    "attitude": "neutral",
    "attentiveness": "normal",
    "reactions": {
      "theft_detected": {
        "mild": "“嘿，朋友，那东西不属于你。”",
        "severe": "他抄起木棍，大声呼喊守卫。",
        "after_calm": "如果你归还并道歉，他可能会原谅你。"
      }

      {
        "trigger": "item_stolen_from_self",
        "notice_probability": 0.6,

      "rumors": ["听说红标帮最近收敛了不少..."]
    }
  }

```

### 5.2 NPC 状态

运行时 NPC 维护以下状态：

```js
{
  awareness: "unaware",    // unaware | suspicious | alert | hostile
  attitude: "neutral",     // friendly | neutral | hostile
  current_location: "stonehill-inn-hall",
  can_see_player: true,
  memory: [
    { event: "theft_attempt_detected", timestamp: 123456 }
  ]
}
```

### 5.3 NPC 反应流程

1. 玩家动作触发 NPC 相关事件
2. 规则引擎根据事件类型、NPC 性格、当前状态选择反应模板级别
3. AI GM 在模板基础上根据性格、记忆、当前情境润色
4. 更新 NPC 状态

### 5.4 延迟发现

偷窃成功后，根据物品显眼程度和 NPC 细心程度决定是否延迟发现：

- `notice_chance` 决定是否最终会发现
- `notice_after` 决定发现时间范围
- 发现后触发新的 NPC 反应事件
- 若剧本未写，默认不延迟发现

### 5.5 商人交易系统

商人 = 带 `merchant` 字段的 NPC。该字段定义货架与动态金币：

```jsonc
"merchant": {
  "gold": 150,                    // 商人动态金币（随交易增减）
  "inventory": [
    { "item_id": "rations", "price": 5, "stock": 10 },   // 售价 + 库存限量（stock 缺省 = 无限）
    { "item_id": "potion-of-healing", "price": 50, "stock": 3 }
  ]
}
```

#### 5.5.1 交互方式

- 地点 NPC 列表点击商人 → 详情弹窗出现"交易"按钮 → 打开**交易弹窗**
- 交易弹窗左右两栏：**商人货架**（物品 + 售价 + 剩余数量 + 购买按钮）｜ **你的背包**（可出售道具聚合 + 收购价 + 出售按钮）
- 物品悬停显示详情（复用 itemEffectText：武器"造成 XdY 类型伤害"、护甲"护甲等级 X"、药水"回复 X 生命值"）
- 商人物品售罄（stock 归零）**直接从货架移除**，不显示"售罄"置灰态

#### 5.5.2 结算与规则

- **确定性接口**（`POST /api/game/buy_item` / `sell_item`），不走 AI tool calling：价格、半价回收、金币增减规则固定，避免 AI 幻觉价格
- 后端权威结算：校验商人/物品/金币/库存 → 扣加玩家金币与商人金币 → 背包增减（装备类进装备栏 `tempEquipItems`）→ 写入 `state.history` 供 GM 感知
- **收购价**：商人库存内物品按售价半价，否则按物品自身 `price` 半价（与前端 `merchantOffer` 一致，half-up）
- **汇总播报**：买卖过程不逐条播报，静默记录到 `tradeLog`，**关闭交易弹窗时一次性汇总**（"爱米利亚与汉斯完成交易：购买了 干粮、火把，花费 7 金币。"）
- **敌对涨价**：商人进入敌对态后，买价统一 +50%（`ceil(price×1.5)`）、收购价进一步压低（卖价更低），前端货架显示涨价价 + ▲ 标记

#### 5.5.3 价格与库存

- 商人价格由 `merchant.inventory[].price` 定义；敌对战前+50%后取 `ceil`
- 库存：`stock`（限量）随购买、偷窃扣减（`sold` + `merchant_theft`），售罄移除货架；未写 `stock` 视为无限
- 商人动态金币 `merchant_states[npc_id].gold` 随买卖增减（买 + 卖 −），不足时拒绝收购

#### 5.5.4 铁匠等卖装备的商人

- 装备类商品（武器/护甲）购买后进装备栏（`tempEquipItems`），不占道具背包；悬停显示"造成 XdY 伤害 / 护甲等级 X"
- 章节物品（如火把）仅有 `equipment_id` 引用时，属性从全局装备库补充（`itemEffectText`）

### 5.6 偷窃系统

偷窃是确定性规则驱动的完整流程，**不提供交易弹窗按钮**，全部通过聊天框对话触发。偷窃动作自动带潜行前置，无需玩家先单独输入"潜行"。

#### 5.6.1 流程

```
玩家输入"偷汉斯的干粮 / 偷商人的钱袋 / 偷格罗斯的剑"
  → ① 潜行判定（未处于隐匿状态时）：隐匿(stealth)检定 vs 在场目击者最高被动感知+警觉
       失败 → 目标警觉 +1，未得手、不质问（按兵不动）
       成功 → 继续
  → ② 巧手(sleight_of_hand)检定 vs DC = 目标被动感知 + 目标警觉
       失败 → 【情况一】警觉 +2、转敌对、NPC 生气骂人，不进入对峙（玩家自决去留）
       成功 → 得手，按 margin 分档：
             ├─ margin < 3        → 【情况二】刚偷到被当场瞥见（人赃并获）→ 立即对峙（flagrante）
             ├─ 3 ≤ margin ≤ 6    → 【情况四】延迟发现（5 秒反应期后质问，discovered）
             └─ margin > 6        → 【情况三】无事发生
```

- **潜行判定**：DC = **与目标同子区域（sub）的在场 NPC** 中最高被动感知 + 各自警觉——子区域相同才互为目击者（线下 DM 按"谁能看见偷窃现场"裁定，如铁匠铺里的格罗斯看不见路边摊的汉斯）；无 sub 的 NPC 视为公共区域互见。躲过最警觉的那双眼睛，一次判定即可（不逐人掷骰）。数据形式：`location.npcs` 支持 `{ "id": "blacksmith", "sub": "铁匠铺" }`，前后端均兼容 str / dict 两种形式
- **巧手判定**：DC = 目标被动感知 + 目标警觉；物品显式 `difficulty` 可覆盖
- **DC 来源为观察者**：潜行/偷窃 DC 由观察者被动感知推导（NPC 数据 `passive_perception` 字段，缺省按 10 + 感知调整），**不逐物品写难度**——与 5e 官方"潜行对抗被动感知、巧手对抗目标感知"一致
- 偷窃目标：商人货架物品（受库存限制）、商人钱袋金币（10%）、NPC 有主物品
- **可偷性**：有 `owner` 的物品默认可偷，无主物走拿取（take）；极少数不可偷的特例（超大固定物、剧情限定物）显式标 `"stealable": false` 覆盖
- **败露概率与检定结果挂钩**：`discovery_p = clamp(0.7 − margin×0.08, 0.05, 0.9)`，检定越接近 DC 越容易败露，大成功几乎不被发现
- **场景物品（有主物）败露**：偷窃成功后同样做概率败露判定——优先用物品 `notice_chance` 字段（如克拉格钱袋 0.4），缺省按上述 `discovery_p` 公式；判定败露 → `mode=discovered` 延迟发现；主人不在场则无人发现，不判定
- **任务关键物品必败露**：剧情关键物品（如甘德伦的地图）加 `"plot_critical": true`，偷窃成功跳过随机**必败露**——NPC 失窃知情写入记忆（`add_memory: item_stolen`，`npc_states[id].memory`），供 P1 延迟反应/事件队列消费推进剧情
- 偷窃完成后无论成败潜行解除
- **统一计价**（对峙赔偿 / 卫兵处置共用 `state.stolen_value`）：赃物价值 = 商人货架售价（原告在场给定时优先）→ 物品 `value` 字段（dict 取 gp）→ 物品 `price` → 缺省 10G，另加偷到的金币；对峙赔偿 ×2、强制搜身/卫兵处置 ×3 均基于此单一来源。**结算播报附带价值构成**（如"赃物价值 5G ×2"）供 AI 叙事，避免 AI 编造单价
- **可选前置潜行**：玩家输入"潜行/躲起来"单独进入隐匿状态——**潜行无需指定目标**（通用隐匿，对在场全部目击者判定，偷窃任意在场 NPC 均视为已潜行）；想瞒过特定某人时可指定目标（仅统计与其同子区域的目击者）。成功后偷窃自动跳过潜行判定
- **商人/钱袋按 margin 分档**（如上四情况）；**场景物品（有主物）保留 notice_chance 判定**：优先用物品 `notice_chance` 字段（如克拉格钱袋 0.4），缺省按 `discovery_p = clamp(0.7 − margin×0.08, 0.05, 0.9)`；判定败露 → `mode=discovered` 延迟发现；`plot_critical`（如甘德伦的地图）偷窃成功必败露；主人不在场则无人发现。场景物品巧手失败同样走情况一（不进入对峙）
- **挣脱/逃脱数值**（NPC 补 `abilities` 力量/敏捷，缺省 10）：
  - **挣脱**（仅被抓住状态可挣脱，全程最多 2 次机会，第 2 次更难 +2）：运动/体操自动取最高（掷两次取高者）vs 商人力量，DC = 8 + 力量调整；vs 卫兵固定 DC 15
  - **敏捷逃脱**：纯敏捷检定（d20+敏捷调整）vs DC = 8 + 对方敏捷调整（商人敏捷 / 卫兵敏捷）
  - 逃脱成功 → **随机传送相邻出口** + **通缉**：普通逃脱 = 案发区域；越狱（重罪）= 整个城市（`wanted_location` 存地点 id 列表）。**引擎播报直接写明被通缉**（角色名），不依赖 AI 猜测

#### 5.6.2 被怀疑（强制对话）

`suspicion` 状态带 `mode` 区分两种对峙场景：

| mode | 触发 | 反应期 | 行为 |
|------|------|--------|------|
| `flagrante`（情况二，人赃并获） | 巧手成功 & margin < 3 | **无**，立即锁定 | NPC 当场抓住质问。选项：给钱了事（×2）/ 欺瞒（DC=15+警觉）/ 威吓（DC=12+警觉，说服当场无效）/ 逃跑（挣脱 → 敏捷逃脱） |
| `discovered`（情况四，延迟败露） | 巧手成功 & 3 ≤ margin ≤ 6 | **5 秒** | 5 秒内可逃离（离开即清除怀疑）；超时仍在原地 → NPC 拦住质问。选项：同意搜身（搜出×2）/ 给钱承认（×2）/ 社交（DC=12+警觉，成功放行，失败 → 强制搜身×3 或逃跑）/ 逃跑（敏捷逃脱）/ 拒绝（叫卫兵） |

- **情况一不进入对峙**：巧手失败只触发警觉+2、敌对、骂人，玩家可自决去留
- 强制对话在聊天框完成（不做按钮）：玩家输入回应，前端关键词正则**确定性触发**（不依赖 AI 意图识别，避免死锁），AI 扮演 NPC 继续质问/叙事。回应关键词含"逃跑/挣脱/溜走"→ `flee`（被抓住时先挣脱，挣脱成功后再次逃跑走敏捷逃脱）
- 对峙阶段**无挣脱**——只有被抓住状态才有（情况二挣脱失败 → `caught` 被抓住状态，第 1 次挣脱用完 → 商人叫卫兵）

#### 5.6.3 卫兵流程（统一，情况二/四汇入）与状态

```
叫卫兵 → 赶来中（1d4 轮，玩家每次动作输入推进 1 轮；询问 GM 不算轮）
  每轮播报：卫兵正在过来 / 卫兵越来越近了 / 卫兵就到门口了
  赶来中选项：
    · 谈判赔偿（同意搜身）×3 → 结束
    · 社交（难度↑，DC=15+警觉）→ 成功私了结束 / 失败保持
    · 逃跑（敏捷 vs 商人敏捷）→ 成功=逃脱[+通缉] / 失败=被抓
    · 若来自情况二（被抓住状态）：可挣脱（第 2 次机会，更难 +2）
卫兵到场 →【默认被抓住状态】→ 要求搜身：
    · 社交 1 次（高难度 DC18）→ 成功化解 / 失败 → 告知即将强制搜查
    · 主动同意搜 → ×3
    · 挣脱（vs 卫兵 DC15）→ 成功 → 敏捷逃脱（vs 卫兵敏捷）→ 成功=随机传送+通缉 / 失败=被按死
    · 失败 → 被按死
被按死 → 没收赃物 + ×3 赔偿 + 关进绝冬城监狱（传送监狱地点，进入 jailed 监狱互动）【仅卫兵有送监狱资格】
被抓住期间总共 2 次挣脱机会，第 2 次失败 → 再也不能挣脱
```

- **通缉**：在 NPC 面前逃跑成功 → 案发区域通缉；越狱（重罪）→ **整个城市通缉**（`wanted_location` 为地点 id 列表，越狱 = 与监狱同 `parent_location` 的所有地点）。**逃脱/越狱成功时引擎播报直接写明被通缉**（角色名，如"爱米利亚在绝冬城被通缉了，进出城都可能被盘查"），并同步注入 AI 上下文【通缉】段（`wanted_names`）；情况四 5 秒反应期内离开 = 无后续（不触发通缉）。通缉实际效果（卫兵主动抓/商人拒卖涨价/洗白途径）属 P1 待做
- **GM 交互规则**：GM 可适度提醒玩家此时可进行的操作；玩家专门询问可详细告知（卫兵赶来中的询问**不算做一轮耗时**）；不强制规定玩家该做什么；玩家操作偏差可提醒（同样不算一轮）

#### 5.6.4 监狱（jailed，被按死后的互动场景）

被按死 → 没收赃物 + 罚金 ×3 → **传送监狱地点**（`neverwinter-jail`，唯一出口"监狱大门"→市场广场），记录 `return_location`（被抓前地点，释放时传回）。监狱里有 **狱卒** NPC（`jailer`，可交谈）。

```
监狱里四选项（聊天框输入，AI 识别 intent=arrest action=...）：
  · 交保释金 100G（"保释/交钱出去"→ pay）→ 当场释放，game_time 不 +8；钱不够提示
  · 撬锁（"撬锁/开锁"→ pick_lock）→ 巧手 vs DC14（须狱卒离开巡逻时）
  · 等待（"等待/消磨时间"→ wait）→ 推进狱卒巡逻轮数（提示剩几轮）
  · 蹲夜（"蹲牢/服刑/我认了"→ serve）→ game_time +8 释放，免保释金
  · 与狱卒闲聊 → 直接对话，不调用工具
```

**狱卒巡逻机制**（用户定：在场真实计时 + 离开按轮数）：

- 狱卒在场：**真实时间倒计时 10-20 秒**（随机），前端 `watchArrest` 倒计时，到点播报"狱卒起身去巡逻了，现在可以撬锁"（本地置 away；后端在玩家下次动作时懒计算确认，权威以后端为准）
- 狱卒巡逻（away）：按玩家**动作轮数**推进（每次动作含撬锁/越狱推进 1 轮；闲聊不算轮），巡逻 1-3 轮后回来；回来时若牢门开着 → **强制关回**（牢门重新锁上 + 警告）
- 玩家动作轮与狱卒回来轮**同一次 tick**：撬锁（1 轮）+ 越狱（1 轮）若正好耗尽巡逻轮数 → 狱卒回来强制关回（需等下次巡逻再撬）

**撬锁判定**（狱卒在场时拒绝："狱卒盯着你，没机会下手"）：

- 成功（total ≥ 14）→ 牢门打开（`cell_open=True`，越狱窗口）→ 玩家可点击"监狱大门"离开
- 失败且 `total ≤ DC-5`（≤9）→ **惊动狱卒**：立刻回来 + 警告"再撬就加刑期"
- 失败 `DC-5 < total < DC`（10-13）→ **无声失败**：狱卒不察觉，可再试

**越狱**：牢门开后点击"监狱大门"（前端 `navigateToLocation` 监狱分支 → `POST /api/game/jail/escape`）→ 推进狱卒轮数 → 狱卒回来 → 强制关回（`cell_open` 复位）；否则越狱成功 → 传送市场广场 + **通缉**（越狱为重罪，`wanted_location` = 整个绝冬城，即与监狱同 `parent_location` 的所有地点 id 列表）+ 清状态，引擎播报"在绝冬城被通缉了，进出城都可能被盘查"。**越狱后进通缉区会被认出/卫兵追捕属 P1 待做**（本次只标记 + 播报）

#### 5.6.5 状态

- `player_stealth`：隐匿状态（目标 NPC + DC；可选前置，偷窃时若已潜行则跳过潜行判定）
- `npc_alerts`：商人警觉（巧手 DC 递增，巧手失败+2/成功+1，潜行失败+1）
- `hostile_npcs`：敌对商人集合（触发交易涨价）
- `suspicion`：被怀疑状态（含 `mode` flagrante/discovered + `detected_at`；flagrante 附加 `grappled` 是否仍被抓住、`social_failed` 社交失败强制搜身标记）
- `caught`：被抓住状态（含挣脱次数 `breakout_used`，共 2 次；仅此状态可挣脱）
- `arrest`：卫兵逮捕状态机（summoned 赶来中 1d4 轮 → arrived 到场 → arrested 被按死 → jailed 监狱；含 `rounds_left`、监狱字段 `jail_guard` present/away + `guard_until` 在场倒计时时间戳 + `guard_away_left` 巡逻剩余轮数 + `cell_open` 牢门是否撬开 + `return_location` 释放返回点）
- `wanted_location`：通缉区域（**地点 id 列表**；普通逃脱 = 案发区域，越狱 = 整个城市（同 `parent_location` 地点）；本次只标记 + 引擎直接播报，效果 P1 落地）
- `merchant_theft`：商人被偷记录（扣减货架库存）

#### 5.6.6 测试阶段数据策略

- 交易/偷窃/监狱的所有结算（金币、背包、商人库存、警觉、敌对、被怀疑、逮捕、监狱、通缉）**仅存 session 内存**，刷新页面即回退

- 后期再做持久化与前后端数据同步

## 6. 玩家角色与技能

### 6.1 角色卡

右侧面板展示完整角色卡，数据来自 `localStorage.currentCharacter` 或后端角色数据。

### 6.2 常用检定

角色卡附近放置两个最常用检定按钮：

- **侦察**：发起感知（Perception）检定
- **调查**：发起调查（Investigation）检定

所有技能检定也可通过角色卡中的技能列表点击触发。

- **检定加值来源**：技能检定 = `d20 + 技能加值`。技能加值以**角色卡 json 中写好的值**为权威（`skills.sections[].skills[].value`，已含熟练/专长/背景修正，由 `rules.skill_bonus` 读取；技能名支持异名映射，如 说服/游说、察觉/侦察、求生/生存）；未列出该技能或角色无 `skills` 结构时**回退属性调整**。前端角色卡显示的技能加值与引擎检定完全一致。

### 6.3 被动技能

当玩家进入地点或发生事件时，后端自动用被动技能比对隐藏信息 DC：

- 被动察觉 ≥ DC：自动发现，GM 叙事中追加
- 被动洞悉 ≥ DC：自动察觉 NPC 隐瞒或说谎
- 被动调查 ≥ DC：自动发现异常装置或机关

被动发现的结果以简洁方式插入叙事，避免叙事过于碎片化。

### 6.4 装备系统

#### 6.4.1 装备库数据

装备库位于 `data/equipment/`（`weapons.json` / `armors.json` / `accessories.json`），每件装备含名称、类型、子类型、稀有度、描述、价格、属性与图标：

```jsonc
{
  "longsword": {
    "name": "长剑",
    "type": "weapon",
    "subtype": "sword",
    "rarity": "common",
    "description": "剑刃笔直的经典单手长剑...",
    "icon": "sword",
    "price": 15,
    "properties": { "damage": "1d8 挥砍", "weight": "3磅" },
    "stats": {
      "category": "melee",
      "damage_dice": "1d8",
      "damage_type": "slashing",
      "finesse": false,
      "light": false,
      "versatile": true
    }
  }
}
```

- `stats`：规则引擎与前端计算用（武器 `category`/`damage_dice`；护甲 `ac_base`/`ac_ability`/`ac_max_dex`/`strength_requirement`；盾牌与饰品 `bonus_ac` 等）
- `icon`：前端按此字段动态加载 `assets/icons/equipment/{icon}.svg`，不写死在前端
- 图标按类统一：近战武器全用 `sword`、远程武器全用 `bow`；护甲 `chestplate`、盾牌 `shield`、衣服 `clothes`、饰品各自图标（ring/amulet/pouch/tools 等）
- 施法焦点类装备（圣徽/奥术法器/材料包）已移除，限制法术释放只保留法术环

#### 6.4.2 属性计算（recalcCharacterStats）

角色加载及装备/卸下/丢弃后，前端重算以下属性并保存回角色 JSON（PUT `/api/characters/{id}`）：

- **AC**：基础 10 + 敏捷调整 → 已装备护甲取最高（轻甲 = 基础+敏调；中甲 = 基础+min(敏调,2)；重甲 = 基础）→ +盾牌 `bonus_ac` → +饰品 `bonus_ac`（如防护戒指 +1）
- **攻击加值** = 熟练加值（`skills.proficiency_bonus`）+ 属性调整值（近战力量 / 远程敏捷）+ 武器加值（`stats.bonus`）
- **伤害** = 已装备武器 `damage_dice`（无武器回退 1d4）

### 6.5 休息系统

**采用 BG3 式设定**（长休后 2 次短休；与线下 5e 短休无限次、消耗生命骰不同，做简化）：

| 类型 | 次数 | 效果 |
|------|------|------|
| **短休** | 每天 2 次（长休重置） | 回一半最大 HP（ceil）、恢复短休充能动作（回气等）、`game_time +1h` |
| **长休** | 消耗 1 份干粮 | 回满 HP、法术位全部恢复、短休重置为 2、恢复短休动作、`game_time +8h` |

- **交互**：角色卡下方"短休/长休"按钮（[侦察/调查旁]）+ 确定性接口 `POST /api/game/rest`，不走 AI
- **HP 后端权威化**：`state.player_hp`（`init_player_hp` 从角色 `combat.hp` "cur / max" 初始化），前端从 `updates.player_hp` 同步——避免前端回传覆盖后端恢复值
- **不追踪行动耗时**：`game_time` 仅休息推进，供延迟发现等少数判定用（线下跑团同样不逐动作计时）
- 多人时休息需投票确认（后续做），当前单人最小实现

### 6.6 施法系统

**架构**：新建 `backend/services/spell_engine.py`（法术引擎），与动作引擎分离。施法统一走 `cast_spell` 确定性结算，前端按钮接口（`POST /api/game/cast_spell`）与 AI 意图（`intent=cast_spell`）共用——和偷窃系统共用 `attempt_merchant_steal` 同一模式。

- **法术位**：按施法等级推导（1 级 2 个 1 环位、2 级 3 个），`state.spell_slots_used` 记录消耗，长休清零；**戏法（0 环）无限施放不消耗**；短休不回法术位（BG3 只有术士短休回位，暂不做术士职业）
- **施法流程**：AI 识别 `intent=cast_spell`（spell_id + target_npc_id）→ 规则引擎校验法术已知/法术位充足 → 消耗法术位 → 结算
- **效果结算**：spells.json 补结构化 `effect` 字段——
  - `"heal NdM+mod"`：确定性恢复玩家 HP（后端权威）
  - `"damage NdM 类型 [save=dex half]"` / `"damage Nx(MdM+K) 类型"`：掷伤害骰 + 目标豁免（DC=8+施法调整+熟练），NPC 受伤标记 `npc_states[id].wounded`；**对指定目标请在聊天框输入"施放X 打向 Y"**（前端按钮默认无目标）
  - 无数值法术（护盾/隐身/睡眠等，无 effect 字段 → narrative）：消耗法术位，AI 只能按【法术描述】叙事，不得凭空加效果（守数据边界铁律）
- **施法属性调整** = max(智力/感知/魅力) 调整（按职业精细表后续可补）
- **前端法术环 UI**：技能法术 tab 按环位分组——戏法（无限施放）+ 1 环（`法术位 x/y`），每个法术块带"施放"按钮（点击直发接口，伤害类提示聊天指定目标）

### 6.7 职业动作（动作引擎）

新建 `backend/services/action_engine.py`（动作引擎），处理非法术类职业动作（回气/回复等），消耗**短休充能资源**（与法术位分离）：

- **回气**（second_wind）：恢复 1d10 + 等级，每次短休/长休后一次
- **回复**（recovery）：消耗一次短休充能，恢复少量 HP
- **斗气如潮**（fighting_spirit）：依赖战斗回合，非战斗不可用（战斗系统待实现）
- 交互：AI 意图 `intent=use_action` + 端点 `POST /api/game/use_action`，确定性结算

## 7. AI GM 架构

### 7.1 模式

支持三种模式，可在冒险过程中切换：

| 模式 | 说明 | 当前状态 |
|------|------|----------|
| 单人 AI 模式 | AI 完全主持，无真人 GM | **已实现**，接入 DeepSeek-V4-Flash |
| AI 辅助 GM 模式 | 真人 GM 在线，玩家输入先到 GM 面板，AI 生成建议回复，GM 可一键采用或修改 | 待实现 |
| 纯真人 GM 模式 | AI 只负责状态管理和检定，回复完全由真人 GM 撰写 | 待实现 |

当前单人 AI 模式实现细节：

- **模型**：`deepseek-v4-flash`
- **API 端点**：`https://api.deepseek.com/v1`（兼容 OpenAI ChatCompletions）
- **配置文件**：`backend/.env` 中配置 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL`
- **实现文件**：`backend/services/ai_gm.py`、`backend/routers/game.py`
- **调用方式**：Tool Calling（Function Calling），仅保留流式端点 `/api/game/action/stream`
  1. `chat_with_tools()`：AI 判断是否需要调用后端 `process_action` 工具（流式 SSE 直通，不预收集）
     - 纯对话/闲聊：AI 直接流式回复（1 次 API 调用，首 token 2-3s）
     - 需要状态变更/检定：AI 返回 tool_call 参数 → 规则引擎执行 → `narrate_with_result()` 流式叙事（2 次 API）
  2. 旧版 `interpret()` + `narrate()` **已删除**，旧端点 `/api/game/action` **已删除**
- **降级机制**：AI 调用失败或 API 不可用时，回退到规则引擎模板回复
- **上下文管理（消息累积）**：
  - 每轮对话不再仅保留最近 4 轮文字，而是将 `state.history` 全部转为标准 API messages 格式（user/assistant），累积追加到请求数组末尾
  - Messages 结构：`[system_prompt, opening_exchange, 历史消息逐轮累积..., current_user_prompt]`
  - 随对话增加 token 自然增长，后续需实现超限裁剪/摘要策略
  - 首轮：`chapter_summary` + 完整场景上下文 + NPC 性格/秘密/目标 + 物品/出口（~2000 chars）
  - 后续轮次：场景锚点（`【当前场景】绝冬城受命 — 矿业公会`）+ 玩家输入（~500 chars），历史对话通过 messages 累积传递
  - AI 思考模式 `reasoning_content` 自动捕获并回传，防止 API 400 错误
  - 切换地点/场景时触发完整上下文重发
- **开场白 AI 预生成**：
  - 后端启动时调用 AI 生成开场叙事（非 TC 调用，纯文本生成），缓存到内存
  - 前端 initGame 时调用 `/api/game/opening` 获取，秒级响应（刷新页面直接读缓存）
  - 开场白背景 exchange 注入 session，作为固定消息参与后续每轮对话，替代首轮重复发送 full context
  - System prompt 禁止 AI 介绍玩家角色身份（玩家已知道自己的角色）
- **技能检定**：全部 D&D 技能已覆盖（侦察、调查、洞悉、隐匿、游说、欺瞒、威吓、巧手、运动、体操等 18 项），TC prompt 中明确各技能触发条件，前端显示中文技能名 + 掷骰结果
- **流式输出**：`chat_with_tools` 在 `StreamingResponse` 内部消费，DeepSeek 每吐一个 token 立即以 SSE 事件发给前端，不再预收集后批量发送

### 7.2 AI 约束

通过以下方式防止 AI 幻觉：

1. **System prompt 硬约束**：`_tc_system_prompt`（439 chars）明确 AI 是 GM 角色，只能基于提供的上下文生成回复，禁止引入未提及的 NPC、地点、物品、剧情。
2. **场景锚点防失忆**：增量轮次发送 `【当前场景】绝冬城受命 — 矿业公会` + 地点描述首句作为锚点，防止 AI 在多轮对话后遗忘场景位置和剧情进度。
3. **首轮完整剧情注入**：`_tc_full_user_prompt` 首行发送 `chapter_summary`（~950 chars），包含章节目标、主要地点、关键 NPC、关键物品、关键任务、GM 提示。
4. **NPC 深层信息暴露**：`_tc_full_user_prompt` 的 NPC 展示包含 `id`、`性格`、`秘密（NPC 会隐瞒）`、`目标`，让 AI 能正确角色扮演而非暴露秘密。
5. **ID 精确匹配**：NPC 格式为 `id=gundren-rockseeker，甘德伦·碎石者`，物品格式为 `id=supplies-neverwinter，绝冬城补给箱（可偷窃）`，AI 调用 tool 时必须使用 id=
6. **剧本分章读取**：只把当前章节内容和必要的前置背景喂给 AI，禁止 AI 读取后续章节。
7. **地点/章节边界检查**：若玩家试图前往未解锁地点或触发跨章剧情，GM 应拒绝或引导回当前场景。
8. **AI 输出为自然语言**：不强制结构化输出，保持叙事自由感；规则引擎从 tool_call 参数提取意图，AI 从 tool_result 提取真实掷骰结果后叙事。
9. **状态变化双重维护**：后端 JSON 状态（物品归属、NPC 状态）由 StateManager 管理；剧情记忆（任务进度、对话上下文）由 AI messages 数组维护。首轮注入后不需要每轮重发。
10. **人称铁律**：system prompt 第一层铁律第 14 条——用角色名称呼玩家角色，GM 叙述不得用"你/我"指代玩家（NPC 台词可用"你"）。**引擎播报同步统一**（steal_engine / intent_dispatch / spell_engine / action_engine 的 GM 叙述全用角色名；玩家消息保留"我"、NPC 台词保留"你"）。
11. **通缉状态注入**：`_build_context` 提供 `wanted_location`（地点 id 列表）与 `wanted_names`（区域名列表），full/lite user prompt 渲染【通缉】段，AI 据此自然体现通缉影响（卫兵盘问、商人警惕）；逃脱/越狱成功时引擎消息已直接播报被通缉，不依赖 AI 猜测。

### 7.3 规则引擎

AI 负责叙事生成，后端规则引擎负责校验。Tool Calling 模式下，AI 通过 `process_action` 工具将意图参数传递给规则引擎：

- 目标是否存在
- 动作是否允许（如物品是否可偷窃）
- 是否需要检定
- 检定 DC 是多少
- 掷骰结果
- 状态变化是否合法

支持的意图：talk、move、advance_scene、perception、investigation、steal、look、take、trade、use_item、resolve_suspicion、combat、other。其中：
- `perception` 携带 `skill=stealth` 时进入潜行分支：隐匿检定成功后设置 `player_stealth`（可偷窃前置）
- `resolve_suspicion`：被怀疑质问时玩家选择（`action` = search/pay/refuse/deception/intimidation/persuasion），由规则引擎执行搜查/赔偿/社交检定

检定支持的全部技能（18 项）：perception、investigation、insight、stealth、persuasion、deception、intimidation、sleight_of_hand、athletics、acrobatics、arcana、history、nature、religion、medicine、survival、animal_handling、performance。TC prompt 中明确各技能触发条件（如"洞悉/察言观色"→insight，"威吓/恐吓"→intimidation）。

规则引擎执行结果通过 tool result 返回给 AI，AI 基于真实结果生成回复——不会出现"AI 描述了成功偷窃但规则引擎说不允许"的矛盾。

### 7.4 状态持久化

当前开发阶段使用**内存会话存储**，会话 ID 由后端生成并通过 API 返回给前端：

- 运行时状态保存在 `GameState` 实例中（`backend/services/game_state.py`）
- 状态变更由 `StateManager` 统一执行（`backend/services/state_manager.py`）
- 每次动作返回 `updates` 字段，前端根据它刷新 UI

后续将补充持久化：

- `data/adventures/{adventure_id}/sessions/session-{id}.json`：地点物品、NPC 状态、玩家背包、任务进度、事件队列
- `data/adventures/{adventure_id}/sessions/session-{id}-log.md`：叙事日志与 GM 笔记，作为后续 AI 加载的上下文

### 7.5 骰子

- 后端实现自动掷骰引擎
- 支持 `1d20+4`、`2d6`、`8d6` 等表达式
- 支持优势/劣势
- 前端先不做动画，后续补充

## 9. 数据流

```
adventure.html 加载
  │
  ├─ 读取 URL 参数：剧本 ID、章节 ID
  │
  ├─ fetch /data/adventures/{adventure_id}/...
  │   └─ 合并全局 NPC 与章节 NPC，合并装备模板与章节物品
  │
  ├─ 渲染界面
  │   ├─ 中央 narrative-log（初始 GM 描述）
  │   ├─ 左侧面板：当前地点 NPC / 物品 / 出口（后端 /api/game/action 返回初始上下文）
  │   └─ 右侧面板：完整角色卡
  │
  └─ 玩家输入（流式 SSE）
      ├─ 前端追加玩家输入到 narrative-log，显示"正在进行检定..."或"GM 正在思考..."
      ├─ POST /api/game/action/stream（SSE，唯一端点）
      │   ├─ 首轮：发送 chapter_summary + 完整上下文（NPC性格/秘密/目标 + 物品/出口 + 角色）
      │   ├─ 后续轮次：场景锚点 + 最近对话 + 玩家输入（~700 chars）
      │   ├─ AI 判断是否需要 tool_call（流式 SSE 直通，不预收集）
      │   │   ├─ 不需要（纯对话）→ 直接流式输出叙事，逐 token 到达前端
      │   │   └─ 需要 → meta 事件先发检定结果 → 规则引擎执行 → narrate_with_result 流式叙事
      │   └─ 切换地点/场景 → 重发完整上下文
      │
      ├─ 前端逐 chunk 追加 GM 回复到 narrative-log（而非全量替换）
      ├─ meta 事件到达时先展示检定结果（中文技能名 + d20 + 修正 + DC + 成功/失败）
      ├─ meta 事件更新 state_changes / updates（物品增减、地点切换、NPC 状态）
      └─ 清空输入框
```

## 11. 设计决策记录

| 决策 | 原因 |
|------|------|
| 取消 7×7 网格导航 | 网格导航更像单机探索游戏，限制了玩家自由宣告动作 |
| 采用 narrative-log + 输入框 | 更贴近线下跑团 GM-玩家对话循环 |
| 左侧面板只显示可见 NPC/物品/出口 | 提供上下文，但不限制玩家自由发挥 |
| 隐藏信息由剧本决定，不硬加 | 避免无意义填充，保证叙事质量 |
| AI 输出自然语言，规则引擎校验 | 保留叙事自由感，同时防止幻觉和非法状态变化 |
| 剧本分章读取 | 控制 AI 上下文范围，防止剧透和跨章跳跃 |
| 不强制结构化输出 | 自由叙事更符合跑团氛围 |
| 偷窃延迟发现由数据驱动 | 在真实感和可控性之间取得平衡 |
| 场景描述中明确提到的物品视为存在 | 贴合线下跑团高自由度，避免 AI 否认场景内可交互对象 |
| 物品/NPC 归属由地点引用而非物品自标记 | 物品和 NPC 模板是独立的，不需要在模板上标记 location。作者只需在地点 JSON 的 `items`/`npcs` 数组中添加引用即可，新增地点不增加物品维护成本 |
| 约束校验链路（地点→可见物品→AI上下文） | AI 只能看到当前地点引用的物品，自动防止"全局物品幻觉"。校验链路：`location.items → get_context_items() → valid_items → _validate_intent_against_context()` |
| Tool Calling 替代两轮 API 调用 | AI 自主判断是否需要后端：纯对话 1 次调用秒回，需要状态变更时才走工具调用 + 第二轮叙事。相比之前每次都强制 interpret+narrate 两轮，显著降低延迟和 token 消耗 |
| 上下文增量发送，首轮完整后续轻量 | messages 数组天然是 AI 的记忆。首轮发送完整场景上下文+chapter_summary+NPC深层信息，AI 之后的回复里已包含场景信息，后续只需发场景锚点+最近对话+玩家输入。切换地点/场景时重发完整上下文 |
| 技能检定自动掷骰 + AI 基于结果叙事 | AI 通过 process_action 传递意图和目标，规则引擎真实掷骰，tool result 返回真实数据。AI 拿到 `{"checks":[{"roll":14,"success":true}]}` 后叙事——不会出现"AI 描述了成功但规则引擎说不允许"的矛盾 |
| NPC 性格/秘密/目标注入上下文 | AI 需要了解 NPC 的深层设定才能正确角色扮演。性格影响回复风格，目标影响行为动机，秘密是 NPC 极力隐瞒的事——被追问时要含糊其辞或转移话题 |
| chapter_summary 首轮注入 | summary.md 包含章节目标、主要地点、关键 NPC/物品/任务、GM 提示。AI 需要知道"整章剧情应该怎么推进"才能做出符合剧本的回复。因内容固定不频繁变化，只需首轮注入 |
| 增量轮次场景锚点 | 24 chars 的纯增量 prompt 导致 AI "失忆"后编造剧情。加入 `【当前场景】绝冬城受命 — 矿业公会` + 地点描述首句（~130 chars）作为锚点，占完整上下文 17% 但能有效防幻觉 |
| SSE 流式直通而非预收集 | chat_with_tools 从 DeepSeek 实时接收 tokens，之前因在 StreamingResponse 外部消费导致预收集后批量发送。改为在 StreamingResponse 生成器内部消费，每个 token 立即以 SSE 事件下发，首 token 到达时间从 6s 缩短到 2s |
| 旧 interpret+narrate 端点删除 | 旧端点每轮 2 次 API 调用（非流式 interpret + 非流式 narrate），interpret system prompt 达 2,015 chars 纯规则冗余。统一到 TC 架构后删除约 720 行旧代码，system prompt 从 2,844 chars 压缩到 439 chars |
| DeepSeek V4 Flash 思考模式处理 | Tool call 场景下模型自动输出 `reasoning_content`，若第 2 次 API 不回传则报 400。chat_with_tools 自动捕获 reasoning_content 并通过 narrate_with_result 回传。思考模式对意图判断有帮助，占延迟比重极小（<5%），不关闭 |
| 历史消息累积替代"贴文本" | 旧方案每轮 messages 全新构建，"最近 4 轮历史"作为纯文本贴入 user_prompt。4 轮之前的信息全部丢失，NPC 状态变化、对话上下文被遗忘。改为 state.history 全部转为标准 API messages 逐轮累积追加，AI 真正拥有完整对话记忆 |
| 开场白 AI 预生成 | 旧方案硬编码 `location.scene_text` 作为开场，无前因后果。改为后端启动时调用 AI 生成开场叙事并缓存，前端加载时秒级获取。开场白背景 exchange 注入 session，后续每轮作为固定消息参与对话，替代首轮重复发送 full context |
| 任务面板 JSON 驱动 + 防剧透 | 任务从 quests.json 加载，仅显示 `status === 'active'` 的任务。点击任务展开子任务，仅显示已完成子任务 + 第一个未完成子任务（防止剧透后续步骤）。点击子任务弹出详情模态框（参照 lobby.html 风格）。完成任务从侧边栏消失。`find-gundren` 等伏击后才触发的任务初始 status 设为 hidden |
| 装备图标类内统一 + JSON 动态关联 SVG | 近战武器统一用 `sword`、远程统一用 `bow`、护甲 `chestplate` 等类内统一图标；前端按 JSON `icon` 字段加载 `assets/icons/equipment/*.svg`，删除了前端写死的图标常量与内嵌 fallback map，槽位图标随装备变化（装盾牌显示盾牌图标） |
| 属性跟随物品加值（recalcCharacterStats） | AC/攻击加值/伤害由已装备物品按 D&D 5e 推导（护甲 AC、盾牌与戒指加值、武器伤害骰、熟练加值）。角色加载与装备变更后重算并保存回角色 JSON，lobby 与 adventure 共享同一份数据，无需页面间交互 |
| 取消武器互斥，武器槽按顺序填充 | 同 category 武器可多件同时装备（支持双持），近战/远程各 2 个槽位按装备顺序填充（第 1 槽 / 第 2 槽）；护甲与盾牌互斥保留 |
| 引擎播报统一角色名 | GM 叙述一律用角色名（配合 AI 叙事第一层铁律 14），为多人模式铺路；NPC 台词保留"你"（真实对话）、玩家消息保留"我"（玩家原话） |
| 技能加值以角色卡 value 为权威 | 角色卡 json 已算好每个技能的最终加值（含熟练/专长/背景修正），引擎 `skill_bonus` 只读取不重算，未列出/无 skills 结构回退属性调整——角色卡显示与检定天然一致，杜绝"卡面 +7 实掷 +3"的偏差 |
| 越狱重罪通缉全城 | `wanted_location` 从单地点改为**地点 id 列表**：普通逃脱 = 案发区域，越狱 = 同 `parent_location` 全城通缉（越狱者不可能回监狱挨抓） |
| 通缉由引擎直接播报 | 旧设计"只标记、由 GM 自然揭示"但 `wanted_location` 未渲染进 user prompt，AI 根本看不到 → 玩家永远不知道被通缉。改为：引擎消息直接写明被通缉 + full/lite prompt 渲染【通缉】段，双保险 |
| 移除 XP 经验系统 | 不做经验系统，角色卡移除 XP 经验条，武器栏中间显示 `Lv.xx` 等级徽章（从角色数据 `level` 字段读取），简化界面 |
| tooltip 事件委托重构 | 原多个 capture mouseenter/mouseleave 共享单一 timer，快速滑过时旧 timer 泄漏导致"幽灵提示框"；改为 mouseover/mouseout 冒泡委托 + hoverTarget 去重 + relatedTarget 判断，从根上消除残留定时器。定位改为"先显示再测量"，修复边侧悬停时提示框一半在视口外的越界问题 |
| 装备栏/物品格子/左侧面板比例缩放 | 尺寸使用 `calc(面板宽 × 系数)`，随面板拖拽等比缩放（字号、高度、间距、圆角同步变化），避免固定像素在小面板下过大或拉伸后失调 |
| 交易走确定性接口而非 AI tool calling | 买卖价格、半价回收、金币结算规则固定，不走 AI 判断避免幻觉价格/误判意图。前端负责展示交互（弹窗/货架/背包/按钮），后端负责权威结算（校验金币库存、扣加金币、写入 history 供 GM 感知）。每笔交易写入 history 让 GM 叙事时能看到"谁买了什么花了多少" |
| 交易关闭时一次性汇总播报 | 买卖过程逐条播报会刷屏且打断叙事。改为静默记录 tradeLog，关闭交易弹窗时聚合一次（"购买了 干粮、火把，花费 7 金币"），保持叙事干净，GM 明细仍可从 history 获取 |
| 商人物品限量 + 售罄移除 | 每件商品带 stock（缺省无限），购买/偷窃扣减；售罄商品直接从货架移除而非置灰，减少无效点击，货架状态更真实 |
| 偷窃强制潜行前置 | 正常流程应为"潜行→感知察觉判定→可偷窃→巧手判定"，故移除交易弹窗偷窃按钮，全部对话触发；未潜行偷窃会被提示先潜行，保证偷窃有隐匿风险前置 |
| 败露概率与检定结果挂钩 | 检定越接近 DC 越容易败露（`0.7 − margin×0.08`），大成功几乎不被发现。比固定概率更有策略感：巧手成功但勉强过关时，商人更容易起疑 |
| 被怀疑 5 秒反应期 | 偷窃败露后立即质问会导致玩家无反应时间。suspicion 带 `detected_at` 时间戳，5 秒内不锁定移动（可逃离），超时后前后端双重锁定 + NPC 质问。注意前端时间戳需换算毫秒（后端 time.time() 为秒） |
| 被怀疑回应走前端关键词确定性触发 | AI 意图识别不稳定（实测多次不调用 resolve_suspicion 工具导致死锁）。改为前端在怀疑状态对聊天输入做关键词正则匹配（搜/给钱/威胁/误会/骗…）直接调 `/api/game/suspicion` 确定性接口，AI 仅扮演 NPC 叙事，保证玩家永远有出口 |
| 被怀疑可用社交检定，失败强制搜查 | 除搜查/给钱/拒绝外，支持欺瞒/威吓/游说检定（DC=12+警觉）：成功放行，失败则商人不由分说直接搜身（走搜查逻辑实查背包），形成闭环避免无限社交拖延 |
| 测试阶段数据 session 内存化 | 交易/偷窃结算仅存 session 内存，刷新回退；前端 saveCharacter（PUT 角色 JSON）停用。角色 JSON 保持初始干净数据作为测试基准，持久化与前后端同步后期再做 |
