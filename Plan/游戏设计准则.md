# 游戏设计准则

本文件记录 DND 项目跨模块通用的游戏设计决策，避免每次开发时重复讨论。涉及 NPC/物品/前端显示等基础设计规则。AI 扮演规则不在本文件范围（在 GM 设计文档中单独定义）。

---

## 一、NPC 数据设计

### 1. 模板复用机制（`_templates`）

- **位置**：跨章节共享的敌人模板放在 `data/adventures/lost-mine-of-phandelver/global/npcs.json` 的 `_templates` 字段。
- **适用对象**：完全重复或高度相似的战斗 NPC（如地精伏击者、狼、哨兵、桥卫、克拉格随从等多只相同个体）。
- **不适用**：
  - 关键 NPC（Boss 有 goals/fears/secrets 完整档案，如 klarg、droop）
  - 商店 NPC（有 merchant 字段，如 market-merchant、blacksmith）
  - 有独立剧情/独立描述的 NPC（如 goblin-sentry-high"打瞌睡的哨兵"）
  - 城镇功能 NPC（如 gate-guard）
- **实例覆盖规则**：模板字段作基础，实例字段覆盖。例如 `ripper` 用 `wolf` 模板，但实例覆盖 `name="利珀"`、`role="克拉格的宠物狼"`、`description="克拉格饲养的凶猛狼宠。"`。
- **前端加载**：前端通过 `_mergeNpcTemplate` 函数合并模板与实例（模板字段为基础，实例同名字段覆盖）。前端不做扁平化数据加工。

### 2. NPC 字段使用规则

| 字段 | 用途 | 显示给玩家 |
|------|------|-----------|
| `id` | 标识 | 系统用 |
| `name` | 名字 | ✅ 显示 |
| `race` / `role` | 种族 · 角色 | ✅ 显示（副标题） |
| `description` | 描述 | ✅ 显示 |
| `status` | 死/昏迷/已离开 | ✅ 显示（徽章） |
| `merchant` | 交易 | ✅ 显示（交易按钮） |
| `personality` | 性格 | ❌ 仅 AI GM 读取 |
| `goals` | 目标 | ❌ 仅 AI GM 读取 |
| `fears` | 恐惧 | ❌ 仅 AI GM 读取 |
| `secrets` | 秘密 | ❌ 仅 AI GM 读取 |
| `attitude` | 敌对/中立/友善 | ❌ 仅 AI GM 读取 |
| `passive_perception` | 被动察觉 | ❌ 仅 AI GM/系统读取 |
| `abilities` | 属性（str/dex 等） | ❌ 仅 AI GM/系统读取 |
| `combat` | 战斗数据（ac/hp/attacks） | ❌ 战斗系统读取 |
| `current_location` | 当前位置 | 系统用 |
| `items` | 携带物品 | 通过战斗回写后由尸体拾取机制处理 |
| `reactions` | 反应 | 仅剧情触发型保留（见下） |

### 3. `reactions` 字段规则

- **剧情触发型**（保留）：标记"某情境下应发生什么剧情"，是剧情契约，不是台词。
  - 例：`sildar.reactions.rescued`（被救后主动告知甘德伦在克拉摩堡 + 提供报酬）
- **台词型**（删除）：预设某情境下 NPC 说什么话。
  - 例：`klarg.reactions.combat.opening`（战斗开场白）、`droop.reactions.captured.plea`（被俘求饶话）
  - 理由：AI GM 应根据 personality/goals/fears 动态生成台词，不依赖预设台词。

### 4. 关键 NPC vs 普通 NPC 档案深度

| 类型 | 示例 | 字段深度 |
|------|------|---------|
| **关键 NPC** | gundren / sildar / nezznar / klarg / droop | 完整档案：personality + goals + fears + secrets + abilities + passive_perception |
| **普通 NPC** | town-guard / jailer | personality + goals（无 fears/secrets） |
| **路人 NPC** | nundro / thaden | 仅基础信息（name/race/role/description） |
| **战斗杂兵** | 地精/狼/哨兵/桥卫 | 用 `_templates` 模板复用，无 goals/fears |

## 二、前端显示规则

### 1. NPC 详情弹窗

**只显示**：
- `name`（标题）
- `race · role`（副标题）
- `description`（描述）
- `status` 徽章（已死亡/昏迷/已离开，来自战斗回写状态）
- 交互按钮（如 `merchant` 字段触发的"交易"按钮）

**不显示**：
- `personality` / `goals` / `fears` / `secrets`（这些是 AI GM 档案，不给玩家看）
- `passive_perception` / `abilities` / `combat`（系统内部数据）

### 2. 物品详情弹窗

按 `type` 字段分三种显示规则：

| 物品类型 | 显示内容 |
|---------|---------|
| **普通物品** | name + description +（可选）拿取按钮 |
| **容器**（`type: "container"`，`contains` 非空数组） | name + description + 内含物品列表 + 每项拿取按钮 |
| **空容器**（`type: "container"`，`contains: []`） | 只显示 name + description，**不显示**拿取 UI |

判断逻辑：`Array.isArray(item.contains)` 走容器分支；`contains.length === 0` 直接 return 空字符串（不渲染拿取 UI）。
