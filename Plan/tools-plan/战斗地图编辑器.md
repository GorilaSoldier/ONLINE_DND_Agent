# 战斗地图编辑器 · 设计文档

> 文件：`tools/map-editor/map-editor.html`（纯前端，单文件自包含）
> 更新：2026-10-31（§7 导出前全格属性检查；§8 更名「地图迷雾」；§10 崖壁画笔）
> 初版：2026-09-13

## 定位
轻量级的地图标注工具，用于在底图上铺网格、框选格子标记地形/高度/出生点，并导出为战斗地图 JSON。**不含连通填充算法、事件检定挂点、浅水半速等后续功能。**

## 目录
- `tools/map-editor/map-editor.html`：编辑器本体（HTML + CSS + JS 内嵌）

## 运行方式
起静态服务器后访问 `/tools/map-editor/map-editor.html`：

```bash
python -m http.server 8080 --directory d:\code\DND
```

支持 `?map=<id>` 直达编辑某张已有地图，例如：
`/tools/map-editor/map-editor.html?map=cragmaw-hideout-overview`

## 已实现功能

### 1. 导入
- **导入图片**：本地选图，编辑器内预览并按其比例铺网格。
- **导入 JSON**：读取已有地图 JSON（格子/高度/出生点/网格参数/地图元信息全部恢复）。
- **?map= 直达**：URL 传 `id` 自动 fetch `/data/combat/maps/<id>.json` 编辑。
- JSON 自带 `image` 字段时自动加载底图，无需重复导图。

### 2. 网格
- 新建时填 `col` / `rows`（默认 30×21）。
- 「铺网格」按规格在图上生成等距网格线。
- 底部实时提示当前每格 ≈ 像素，并校验是否正方形（非正方形时标红警告，建议调整图片或 cols/rows）。

### 3. 画笔类型（均可走不进去）
| 类型 | kind | 颜色 | 说明 |
|------|------|------|------|
| 墙 | `wall` | 灰 | 洞壁/建筑墙 |
| 树 | `tree` | 绿 | 树木/丛林 |
| 岩石 | `rock` | 棕 | 石头/地形 |
| 崖壁 | `cliff` | 蓝灰 | 场景内的垂直崖面；无限高，挡视线/挡光/挡移动（2026-10-29 新增） |
| 水 | `water` | 蓝 | 统一视为不可通行（暂不做浅水半速） |
| 背景 | `background` | 黑 | **地图上不存在的占位区**（洞外虚空）：不可通行，但**不挡视线/光线**（相当于地图外的无区域格子） |
| 擦除 | — | — | 清空选定格（右键可直接擦除） |

> 示例：`{"col": 0, "row": 16, "kind": "wall"}`

> 每个画笔按钮带 `title` 悬浮说明（2026-10-29 新增）：鼠标悬停即显示该笔刷的可通行性、是否挡视线/光线、开关语义等；说明文案与上表保持一致。

### 4. 高度 z
- 每格高度 `z`（整数，默认 0）。
- 非零格导出到 **独立 `heights[]` 数组**，不破坏现有障碍结构。
- 战斗端暂不读取 `heights`（现有代码忽略未知字段），待实现"爬坡按高度差耗移动力"时再接入。
  - **（2026-10-29 更正）** 已接入：高度用于移动/跳跃/坠落与迷雾高度视线（见[战斗地图方案 7.3](../模块1/模块1-战斗地图系统设计方案.md)），不再忽略。
- 示例：`{"col": 5, "row": 3, "z": 1}`

### 5. 出生点（当前为旧结构，见「待办」）
- 现有：玩家 / 敌人两类，固定坐标。
- 导出后写入 `spawns.players[]` / `spawns.enemies[]`。

### 6. 交互
- 左键按住拖动 = 框选并填充当前画笔。
- **右键按住拖动 = 擦除**，并屏蔽浏览器默认右键菜单。
- 触屏支持。
- 「新建」清空重来。

### 7. 导出 JSON
结构对齐 `data/combat/maps/triboar-trail-ambush.json`，并扩展高度、迷雾与光源：

```json
{
  "id": "cragmaw-hideout-overview",
  "name": "克拉摩窝点·总览",
  "image": "/pic/地图/洞穴地图总览.jpg",
  "meters_per_cell": 1.5,
  "grid_cols": 30,
  "grid_rows": 21,
  "obstacles": [ { "col": 0, "row": 16, "kind": "wall" } ],
  "heights":   [ { "col": 5, "row": 3, "z": 1 } ],
  "fog_zones": [ { "col": 0, "row": 1 } ],
  "light_sources": [ { "col": 12, "row": 7 } ],
  "spawns": {
    "players": [ { "col": 15, "row": 10 } ],
    "enemies": []
  }
}
```

- 空数组字段可省略（`obstacles` / `heights` / `fog_zones` / `light_sources` 无内容时不输出；无 `fog_zones` = 该图无地图迷雾，无 `light_sources` = 该图无固定光源）。
- 导出为**浏览器下载**，需手动放入 `data/combat/maps/`（未来可就后地点写回）。
- **导出前检查（2026-10-31 新增）**：逐格检查全图（`cols × rows`）是否至少有 1 个属性（地形 kind / 高度 z≠0 / 地图迷雾 / 光源 / 出生点）。存在未标注格时弹确认框，列出数量与前 6 个坐标，提示"若该图使用了地图迷雾，这些格开战时会直接可见"，可取消导出。目的：防止漏涂迷雾导致开局漏亮，不改变任何格子的通行性。

### 8. 地图迷雾画笔（2026-09-13 新增，2026-10-30 更名）
- 画笔「地图迷雾」（紫色）：给格子打独立 `fog` 标记（非地形 kind，可与障碍/高度/光源共存）。
- **效果**：被标记的**迷雾区域不可见**（最上层黑幕）；玩家**经过此区域后，迷雾消除**（永久揭开，不回填黑幕）。
- **开关语义**：已涂地图迷雾的格再涂一次即取消；擦除画笔仍会清掉整格（含地图迷雾）。
- 导入/导出走地图 JSON 的 `fog_zones` 格集合；战斗端（`js/combat/fog.js`）消费为最上层黑幕。
- 迷雾机制设计见 [文字冒险方案 11.4](../模块1/模块1-文字冒险界面设计方案.md)（2026-09-12 定稿）。

### 9. 光源画笔（2026-09-28 新增）
- 画笔「光源」（橙色）：给格子打独立 `light` 标记（非地形 kind，可与障碍/高度/地图迷雾共存）。
- **开关语义**：同「地图迷雾」画笔——已涂的格再涂一次即取消；擦除画笔仍会清掉整格（含光源）。
- 导入/导出走地图 JSON 的 `light_sources` 格集合；战斗端（`js/combat/fog.js`）的 `revealLights` 把固定光源与单位携带光源（已装备火把/提灯）统一为同一套揭示（光源看得见 + 观察者看得见双重视线）。
- **半径统一 4 格**（常量，同火把/提灯），故光源格**不存半径字段**。
- 光源机制设计见 [文字冒险方案 11.4](../模块1/模块1-文字冒险界面设计方案.md)（2026-09-28 定）。

### 10. 崖壁画笔（2026-10-29 新增）
- 画笔「崖壁」（蓝灰）：地形 kind `cliff`，走不进去；**无限高**，挡视线、挡光源、挡移动（已并入 `SIGHT_BLOCKING_KINDS`）。
- 与「背景」的区别：**背景 = 地图上不存在的占位区**（洞外虚空），不可通行但**不挡视线/光线**；**崖壁 = 场景内的垂直岩面**，不可通行且**挡视线/挡光线**。两者语义不同、视线行为也不同，方便后续按 kind 做差异化表现。
- 用途：画在崖沿外侧一格，阻断"站在崖顶看到崖壁外下方"的视线，也阻断谷底向崖沿的漏光；比依赖高度阈值更可控。
- 摆放建议：沿崖沿铺一格即可；不要铺在可行走谷底（会占掉落点/阻挡走位）。

## 设计约定
- 网格默认**正方形**；图片宽高比应接近 `cols / rows`，编辑器提示但不可强制。
- 地图 JSON 精简存储：只存非默认（非平地、非高度0）的格子。
- `heights` 为新增字段，战斗代码读到会忽略，向后兼容。

## 待办 / 后续方向
- **【待办】出生点模型升级**（讨论中，未实现）：
  - 玩家落位：**不在编辑器内指定具体位置**。编辑器只标注「玩家可选落点范围」（图上区域，可留空）；真正让玩家挑落点是在 **adventure → combat-map 过渡页**，且若编辑器未提供范围，则**除不可选（障碍）外的所有格子均可选**。
  - 出生点细分为**三阵营**：玩家 / 队友 / 敌人，用候选阵营格标记，可留空。
  - 地图 JSON 只存"候选格 + 阵营"；具体放哪只 NPC 由**当前章节/遭遇配置**提供并填入。
  - 需战斗端配合改造（`spawns.players[0]` 那套逻辑），范围待确认（只改编辑器 A / 编辑器+战斗端 B）。
- 【待办】后端写回 / 指定保存路径功能。
- 【待办】跳跃可跨障碍白名单：战斗端 `main.js` 的 `JUMP_CROSSABLE` 当前只含 `water`（仅水可跳过，墙/树/岩/崖壁/背景不可跳）。后续需要时可扩展该集合（如允许跨 tree/rock）。
- 不做（明确排除）：连通填充算法、事件检定挂点、浅水半速、地图渲染美化。
