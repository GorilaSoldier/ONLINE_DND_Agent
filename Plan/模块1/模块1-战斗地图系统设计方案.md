## 1. 概述

### 1.1 设计目标

为 DNDBOX 提供**基于地图的战斗交互层**。战斗发生在地图上：玩家通过点击 token、移动、攻击、施法等方式与敌人对抗，摆脱纯文字的战斗描述。

当前版本（本文档）已实现**完整战斗闭环 + 嵌入冒险流程 + BG3 风格倒地系统**：

> **地图底图 + 网格 + 角色 token + 移动范围可视化 + 障碍物阻挡 + 攻击/施法/动作 + 回合制 + 敌人 AI + 战斗结束判定 + M6 嵌入冒险流程（遭遇自动跳转 + 战斗结果回写）+ M5.10 倒地系统（死亡豁免/扶起队友/苏醒回合限制/敌人智能补刀）**

### 1.2 核心设计理念

| 要素 | 设计 |
|------|------|
| **定位单位** | 格子（正方形网格），token 吸附格子中心 |
| **范围判定** | 圆形（半径 = 米数），**圆只筛选格子，不参与定位** |
| **可达计算** | 扩散算法（水波式），绕开障碍物 |
| **数据单位** | 角色卡存**米**，地图显示**格**，1 格 = 1.5m |
| **交互** | 点击动作按钮 → 自动选中角色 → 显示射程圆+目标高亮 → 点击目标结算 |
| **结算** | 前端本地掷骰引擎（actions.js），D&D 5e 规则，不依赖 AI GM |
| **回合** | 真掷先攻（d20+敏捷），玩家回合 ↔ 敌人回合轮转 |
| **嵌入冒险** | adventure.html 进入含 combat 遭遇的 scene 时自动跳转 combat-map.html，战斗结束回写 HP/战利品/线索 |
| **状态传递** | sessionStorage 传 encounterContext（进入）与 combatResult（回写），URL 仅传 encounterId 标识 |

### 1.3 页面定位

- 文件：`combat-map.html`（独立页面 + M6 嵌入模式）
  - 独立调试模式：无 URL 参数，回退到写死的 4 只地精 + elias 角色
  - 嵌入模式：URL `?encounter=xxx` 从 sessionStorage 取 encounterContext 动态加载
- 文件：`adventure.html`（M6 接入点）
  - `navigateToScene` 检测 `scene.events` 中 `type:'combat'` 的遭遇 → 自动跳转
  - `consumeCombatResult` 在 initGame 中接收战斗结果回写 state
- 复用 lobby.html 的色彩体系（CSS 变量）
- 三栏布局：左侧场景上下文 + 中央战斗地图 + 右侧角色卡
- 战斗场景由地图配置 `scene` 字段关联冒险章节（如 `ch1-scene2` 三猪小径）

```

│  [返回]                         DNDBOX                     │  ← top-bar
├────────────────────────────────────────────────────────────┤
│  左侧面板  │           中央区域             │   右侧面板    │
│           │  ┌─────────────────────────┐  │               │
│ 当前场景   │  │  🗺 三猪小径 · 伏击点     │  │   角色卡       │
│ ├ 人物    │  ├─────────────────────────┤  │   属性/技能    │
│ ├ 物品    │  │                         │  │   背包/法术    │
│ │         │  │     combat-map          │  │               │
│ 队伍成员   │  │     (底图+网格+token)     │  │  技能&法术 tab │
│ 当前任务   │  │                         │  │  (动作面板)    │
│           │  └─────────────────────────┘  │               │
│           │  [● 状态栏: 战斗开始!先攻...]   │               │
│           │  [结束回合]                   │               │
└───────────┴───────────────────────────────┴────────────────┘
```

### 2.1 顶部栏

- 左侧：返回按钮
- 中央：DNDBOX 品牌

### 2.2 中央区域：战斗地图

- **底图**：PNG 图片（如 `三猪小径.png`），按容器比例缩放
- **网格**：覆盖在底图上的正方形网格（`grid_cols × grid_rows`）
- **障碍层**：树/岩石/墙等不可通行格（半透明深色覆盖）
- **高亮层**：可移动/可选目标格（蓝色半透明 + 边框）
- **token 层**：圆形角色 token（玩家蓝 / 敌人红），含 HP 条 + `HP:xx` + `Lv.xx`
- **射程圆**：攻击/法术选择目标时显示（红色虚线，半径=米数换算）
- **飘字层**：伤害（红 `-x`）/ 治疗（绿 `+x`）短暂上浮动画

#### 2.2.1 状态栏

- 显示当前战斗状态（先攻结果 / 当前回合 / 结算播报 / 操作提示）
- **结束回合按钮**：玩家回合可用，点击切到敌人回合
- 图例：玩家 / 敌人 / 可移动格

### 2.3 左侧面板：场景上下文

与文字冒险界面一致，但显示**当前战斗地点的数据**（由地图配置 `scene` 字段切换）：

- **人物**：当前地点的 NPC（如 4 只地精伏击者），点击看详情
- **物品**：当前地点的物品（如 空地图匣、散落的物资）
- **队伍成员 / 当前任务**：从冒险章节加载

### 2.4 右侧面板：角色卡 + 动作面板

完整角色卡（与文字冒险一致），其中**技能&法术 tab 兼作战斗动作面板**：

| 区块 | 内容 | 交互 |
|------|------|------|
| **攻击** | 近战攻击 (+x / 伤害骰)、远程攻击 | 需目标：射程圆 + 敌人高亮 → 点击结算 |
| **常规动作** | 跳跃 / 投掷 / 冲刺 | 跳跃：选落点（无视障碍）；冲刺：移动翻倍；投掷：需目标 |
| **职业动作** | 斗气如潮 / 回复 / 附加攻击 | 自身目标，点击直接生效 |
| **戏法** | 火焰箭（1d10，9米，无限施放） | 需目标 |
| **1 环法术** | 治愈术（触碰） | 需目标 |

> 无需先点角色：点动作按钮自动选中己方 token 并进入对应状态。

## 3. 交互模型

### 3.1 状态机

```
idle ──点击己方token──▶ selected ──点击可达格──▶ moving
  ▲                        │  ▲                     │
  └──────结束回合/取消───────┘  └──动画结束──▶ idle
                          │
                          └──点动作按钮──▶ targeting（选目标）
                                          │  └─点敌人▶ 结算 ──▶ selected
                                          └─点「跳跃」──▶ jumping（选落点）
                                                             └─点空地▶ 跳跃移动
```

| 状态 | 触发 | 行为 |
|------|------|------|
| `idle` | 未选中 | 点己方 token 进入 selected |
| `selected` | 选中 | 显示移动范围（蓝格），可点动作按钮 |
| `moving` | 点击可达格 | 平滑移动，期间禁止操作 |
| `targeting` | 点攻击/法术 | 射程圆 + 射程内敌人红圈高亮，点敌人结算 |
| `jumping` | 点跳跃 | 跳跃范围蓝格高亮，点落点飞跳（无视障碍） |

### 3.2 回合轮转

```
战斗开始 → 掷先攻（d20+敏捷）→ 先手方行动
    [玩家回合] 自由移动/攻击/施法/动作 → 点「结束回合」
    → [敌人回合] 存活地精逐只 AI 行动（间隔 700ms）
    → 回到 [玩家回合] ... 循环直到战斗结束
```

- 非玩家回合（`enemy`）禁止一切玩家操作（地图点击 / 动作按钮均拦截）
- 玩家死亡 → 战斗失败；敌人全灭 → 战斗胜利（地图中央横幅提示）

## 4. 单位体系：米 ↔ 格

### 4.1 换算桥

```
1 格 = 1.5 米（D&D 5e 标准：1 格 = 5 英尺 ≈ 1.5m）
```

地图配置文件声明比例尺，前端启动时换算：

```json
{
  "meters_per_cell": 1.5,
  "grid_cols": 18,
  "grid_rows": 24
}
```

### 4.2 换算示例

| 角色卡数据（米） | 换算 | 用途 |
|---|---|---|
| `move_speed: "4.5m"` | 4.5 ÷ 1.5 = 3 格 | 扩散步数（elias） |
| `melee_range: "1.5m"` | 1.5 ÷ 1.5 = 1 格 | 近战距离 |
| `ranged_range: "6m"` | 6 ÷ 1.5 = 4 格 | 远程射程 |
| 法术 `range: "9米"` | 9 ÷ 1.5 = 6 格 | 火焰箭/火球术射程 |

> 说明：BG3 中火焰箭/火球术为 18 米（12 格）。因战斗地图仅 18×24 格，射程 12 格几乎覆盖全图，已压缩到 9 米（6 格）保证比例协调。

## 5. 地图与网格

### 5.1 地图配置数据结构（`data/combat/maps/<map_id>.json`）

```jsonc
{
  "id": "triboar-trail-ambush",
  "name": "三猪小径·伏击点",
  "image": "/pic/地图/三猪小径.png",
  "scene": "ch1-scene2",            // 关联冒险章节场景，驱动左侧面板数据
  "meters_per_cell": 1.5,
  "grid_cols": 18,
  "grid_rows": 24,
  "obstacles": [
    { "col": 6, "row": 10, "kind": "wall" },   // tree / rock / wall
    { "col": 7, "row": 11, "kind": "wall" }
  ],
  "spawns": {
    "players": [{ "col": 2, "row": 12 }],
    "enemies": [{ "col": 14, "row": 9 }, { "col": 15, "row": 11 }]
  }
}
```

### 5.2 障碍物（不可通行格子）

- 障碍类型：`tree`（树）/ `rock`（岩石）/ `wall`（墙）
- 全部进入 `obstacleSet`（`"col,row"` key），用于移动扩散断开 + 跳跃落点校验
- 窄墙可绕行；封死路的墙使其后方格子天然不可达（由扩散保证）

### 5.3 障碍物渲染

- 每个障碍格渲染半透明深色覆盖层，直接覆盖底图对应格子

## 6. Token 设计

### 6.1 外观

- 圆形，直径约 0.8 格，圆心显示角色名首字（玩家「埃」/ 敌人「地」）
- 阵营配色：玩家蓝色、敌人红色（复用 FACTION_STYLES）
- **HP 条**：圆形下方横条，按 HP 比例变色（绿 → 黄 → 红）
- **HP 数字**：右上角 `HP:xx`
- **Lv 徽章**：左上角 `Lv.x`（玩家从角色 level 读取，敌人默认 1）

### 6.2 定位

- token 吸附格子中心，移动时沿格子路径平滑滑动（CSS transition）
- **命中区**：至少 48px 方形（小地图保证易点中）；跳跃选落点期间临时置为 `pointer-events:none` 防吞点击

### 6.3 状态

| 状态 | 表现 |
|---|---|
| 空闲 | 正常显示 |
| 选中 | 白色高亮描边 + 蓝色移动范围 |
| 可攻击目标 | 红圈高亮（射程内敌人） |
| 死亡 | 半透明（opacity 0.35） |

## 7. 移动与跳跃

### 7.1 移动交互流程

```
点动作/点击己方 token → 计算移动范围（圆筛选 ∩ 扩散可达）
    → 蓝色高亮可选格 → 点击目标格 → 沿路径平滑移动 → 恢复状态
```

- 移动范围 = 移动半径圆内（格子中心距离 ≤ move_speed 米）∩ 扩散可达（走得过去）
- 可移动格点击后走最短路径（回溯步数表）

### 7.2 跳跃（跨障碍）

D&D 5e 远跳规则：跳跃距离 = **力量值 英尺**（每格 5 英尺）。

```
jumpRangeCells = round(力量值 / 5)     // elias 力量17 → 3 格
```

- 点「跳跃」→ 蓝色高亮跳跃落点范围（半径 3 格，排除障碍格）
- 点落点 → token 飞跳过去，**路径无视障碍**（可跳越墙/树/岩石）
- 落点校验：不能是障碍格 / 不能是其他生物占据格
- 高度系统（登高/跳高台）待后续实现

## 8. 动作经济（D&D 5e Action Economy）

### 8.1 回合资源

玩家在自己的回合拥有四类资源，各用各的，互不占用（对齐 BG3 / D&D 5e RAW）：

| 资源 | 每回合 | 恢复 | 展示 |
|---|---|---|---|
| **动作 Action** | 1 | 结束回合重置 | 资源条 `动作 ●` |
| **附赠动作 Bonus Action** | 1 | 结束回合重置 | 资源条 `附赠 ●` |
| **移动力 Movement** | 1 倍速度（elias 4.5m） | 结束回合重置（不结转） | 资源条 `移动 x.x米` |
| **反应 Reaction** | 1 / 轮 | 自己回合开始时恢复 | 待 M7 阶段实现借机攻击时启用 |

> 资源条位于地图下方状态栏（仅玩家回合显示，敌人回合隐藏）。

### 8.2 动作归类（读 spells.json `action_type`）

| 类型 | 文案 | 消耗 | 例子 |
|---|---|---|---|
| 动作 | `1动作` | action | 近战/远程攻击、火焰箭、治愈术、冲刺、投掷、回复 |
| 附赠动作 | `附赠动作` | bonus | 跳跃、回气（Second Wind） |
| 自由动作 | `自由动作` | free | 动作如潮（Action Surge） |
| 被动 | — | 不消耗 | 巨武器使用（不可点击展示块） |

按钮右上角显示类型角标（`动作` / `附赠` / `自由`），预算耗尽置灰。

### 8.3 回合内限次特性

| 特性 | 来源 | 限制 | 消耗 |
|---|---|---|---|
| **回气 Second Wind** | 战士 1 级 | 每短休 1 次（战斗内 1 次） | 附赠动作，恢复 1d10 + 战士等级 HP |
| **动作如潮 Action Surge** | 战士 2 级 | 每短休 1 次（战斗内 1 次） | 自由动作，本回合 **获得 1 个额外动作** |
| **额外攻击 Extra Attack** | 战士 5 级 | 被动 | 攻击动作自动结算 2 次掷骰，不另耗资源 |

> elias 4 级：已有回气 + 动作如潮；5 级后激活额外攻击被动。

### 8.4 移动力预算与拆分

- 移动力按**米**计算存储，按**格**走扩散（斜走消耗 √2 格 ≈ 2.12 米）
- 高亮范围 = 剩余移动力内的可达格子；走一格扣一格成本（×1.5 米）
- 支持 **移动 → 攻击 → 再移动** 拆分（点击移动后保持选中，剩余移动力见资源条）
- 冲刺（Dash，动作）：额外获得一倍移动力（已消耗不返还）
- 跳跃（附赠动作 + 移动力）：消耗距离 × 1.5 米移动力

### 8.5 交互

- 战斗外（`combatPhase === 'idle'`）不限制
- 敌人回合所有玩家操作拦截，资源条隐藏
- 敌人 AI 对等执行"移动力 + 1 动作"：够不着先移动，射程内再攻击

## 9. 先攻与回合顺序

### 9.1 先攻掷骰（D&D 5e RAW 逐个）

战斗开始时，**每个生物单独掷先攻**：`d20 + 敏捷调整值`，降序排列形成 initiative order。同值时玩家优先。

```js
// elias dex 16 (+3)：d20+3；地精 dex 14 (+2)：d20+2
initiativeOrder = [
  { token, initiative: 18, faction: 'enemy',  name: '地精伏击者' },
  { token, initiative: 15, faction: 'player',  name: '埃利亚斯·灰溪' },
  { token, initiative: 12, faction: 'enemy',  name: '地精伏击者' },
  ...
]
```

> 旧版（v1.0 及之前）为简化版：玩家掷一次，地精群体取最高，两方轮换。v1.2 升级为 RAW 逐个先攻。

### 9.2 回合顺序头像条（地图上方横向，BG3 式）

位于 top-bar 下方、地图上方的横向头像条：

```
┌──────────────────────────────────────────────┐
│ [头像]    [头像]    [头像]    [头像]    [头像]  │  ← initiative-bar
│  地精19   埃利亚斯15  地精12   地精10   地精8   │
│  (current发光) (next半亮)                     │
└──────────────────────────────────────────────┘
┌──────────────────────────────────────────────┐
│              combat-map                       │
└──────────────────────────────────────────────┘
```

| 状态 | 视觉 |
|---|---|
| **当前行动者** | 白色描边发光 + 上浮 2px + 浅色背景 |
| **下一个行动者** | 半亮 + 浅描边，提示"下一个该谁" |
| **死亡** | 灰度滤镜 + 透明度 0.3 + 首字删除线 |
| 等待中 | 正常显示 |

头像复用 token 阵营色（玩家蓝 / 敌人红），首字 + 名字 + 先攻值。

### 9.3 逐个轮转

```
战斗开始 → rollInitiative → 渲染头像条（1.2 秒展示顺序）
  → activateCurrent(0)
      ├─ 若是玩家 → 玩家回合（等操作 → endPlayerTurn → advanceInitiative）
      └─ 若是敌人 → runSingleEnemyAct（移动+攻击）→ advanceInitiative
  → advanceInitiative: currentInitIndex++，跳过死亡，到末尾回 0（轮数+1）
  → 检查战斗结束（敌人全灭 → 胜利；玩家死亡 → 失败）
  → activateCurrent(下一个)
```

- 敌人不再是"一次跑完所有再回玩家"，而是**逐只按先攻顺序行动**
- 玩家和敌人交替进行，完全对齐 BG3 / D&D 5e RAW
- 状态栏提示「第 X 轮 · <角色名>的回合」/ 「第 X 轮 · <角色名>行动中...」

### 9.4 死亡与顺序维护

- 敌人 HP ≤ 0 → 标记 `dead`，头像条变灰，advanceInitiative 自动跳过
- 玩家死亡 → endCombat(false)
- 所有敌人死亡 → endCombat(true)
- 战斗结束后头像条保留最终局面（死亡者变灰，便于复盘）

## 10. 战斗系统

### 10.1 回合制

| 环节 | 实现 |
|------|------|
| **先攻** | 真掷骰（RAW 逐个）：每个生物 `d20 + 敏捷调整值`，降序排列，同值玩家优先（详见第 9 章） |
| **玩家回合** | 受动作经济约束（1 动作 + 1 附赠 + 移动力），点「结束回合」切到下一个行动者 |
| **敌人回合** | 按先攻顺序逐只行动（移动力 + 1 动作），间隔 600ms，结束后推进到下一个 |
| **回合锁定** | `combatPhase`（idle/player/enemy/victory/defeat），非 player 回合禁止操作 |

### 10.2 结算引擎（`js/combat/actions.js`，前端本地掷骰）

| 结算 | 规则 |
|------|------|
| **普攻** | `d20 + 攻击加值` vs 目标 AC；命中掷伤害骰；重击(20)伤害翻倍；1 自动失手 |
| **额外攻击** | 战士 5 级被动：攻击动作自动结算 2 次掷骰 |
| **法术** | 解析 `effect` 字段：`damage NdM 类型` / `heal NdM+mod` / `narrative`；带豁免的目标豁免判定 |
| **自身动作** | 回气（1d10+等级，附赠）/ 回复（1/4 最大 HP，动作）/ 冲刺（移动力+1倍，动作）/ 动作如潮（额外动作，自由） |
| **骰子** | 兼容骰子格式（`1d8+3`）与旧范围格式（`6~16`） |

### 10.3 玩家攻击/施法

```
点右侧动作按钮 → 动作预算校验（trySpendCost）→ 自动选中己方 token → targeting 状态
    → 射程圆（攻击：近战1格/远程4格；法术：range 字段）
    → 射程内敌人红色高亮 → 点击敌人 → resolveAttack/resolveSpell 结算 + spendCost 扣预算
    → 敌人 token 飘红字 + HP 扣减 → 右侧角色卡 HP 同步 → refreshCombatButtons 置灰
```

### 10.4 敌人 AI（地精，对等动作经济）

| 阶段 | 行为 |
|---|---|
| 移动阶段 | 短弓射程（4 格）外 → 向玩家移动（消耗移动力） |
| 动作阶段 | ≤1 格用弯刀近战、≤4 格用短弓远程；够不着则原地待命 |

- 攻击复用 `resolveAttack`，伤害扣到玩家 token，飘红字 + 右侧角色卡同步
- 敌人数据来自 `npcs.json` 的 `combat` 字段（ac / hp / move_speed / attacks）

### 10.5 战斗结束

- 玩家击杀最后一只敌人 → **胜利**（绿色横幅「⚔ 战斗胜利」）
- 玩家 HP ≤ 0 → **失败**（红色横幅「☠ 战斗失败」，token 变灰）
- 结束后禁止继续操作，资源条隐藏

### 10.6 倒地与死亡豁免系统（BG3 风格，v1.6）

对齐《博德之门 3》的 Downed / Death Saves / Help / 智能补刀机制，替代"HP=0 即死"的简化规则。让玩家在 0 HP 时进入昏迷倒地状态，依靠死亡豁免掷骰与队友救援决定生死，保留 D&D 5e 死亡三段判定框架。

#### 10.6.1 倒地触发

| 触发条件 | 行为 |
|---|---|
| 玩家 HP ≤ 0（首次） | 进入 `downed=true`，初始化 `deathSaves = { successes: 0, failures: 0, stable: false }`；token 透明度降至 0.55；战斗日志「<角色> 倒下，进入昏迷状态」 |
| 敌人 HP ≤ 0 | 杂兵惯例直接 `dead=true`，不进入倒地（保留原状） |
| 玩家昏迷中再受伤 | 见 10.6.3 |
| 稳定状态受伤 | 失去 `stable`，恢复死亡豁免流程（5e RAW） |

#### 10.6.2 死亡豁免掷骰（玩家回合开始时）

| 骰值 | 结果 |
|---|---|
| 自然 20 | 立即恢复 1 HP 苏醒；本回合**只能用附赠动作**（`justRevived` 标记） |
| 自然 1 | 失败 +2 |
| ≥ 10 | 成功 +1；累计 3 次 → **稳定（Stable）状态** |
| 2~9 | 失败 +1 |
| 累计 3 次失败 | **死亡** → `dead=true` → `endCombat(false)` 战斗败北 |

掷骰不加调整值（5e RAW）；昏迷角色不能行动，回合自动结束（自然 20 苏醒后可执行附赠动作）。

#### 10.6.3 稳定状态

- **3 次成功后进入稳定状态，不再掷骰，但仍昏迷**——关键设计：与"3 成功自动回 1HP 苏醒"不同，必须靠队友扶起或治疗才苏醒
- 解决"角色永远不会死"问题：稳定 ≠ 起身，敌人补刀仍可杀死
- 稳定状态受伤 → `stable` 重置为 false，恢复死亡豁免流程
- 稳定时回合仍占回合，日志「<角色> 已稳定（昏迷中，等待队友扶起或治疗）」

#### 10.6.4 扶起队友（help_downed 动作）

`spells.json` 新增动作 `help_downed`（1 动作 / 触碰 / effect: revive），elias.json `action_ids.normal` 已加入该动作。

| 项 | 规则 |
|---|---|
| 目标范围 | 触碰（1 格，含斜角，Chebyshev 距离 ≤ 1） |
| 目标条件 | faction ∈ {player, ally} 且 `downed=true` 且 `dead=false` |
| 效果 | 目标恢复 1 HP 苏醒，重置 deathSaves 计数 |
| 苏醒回合限制 | 被扶起者若正在当前回合行动 → `justRevived=true`，本回合只能用附赠动作（动作/移动力归零） |
| 失败处理 | 目标非己方 / 已死亡 / 未倒地 → 日志提示，不消耗动作预算（在 `resolveRevive` 早返回） |

目标选择：`showTargetables` 中对 `effect` 字段以 `revive` 开头的法术/动作只高亮倒地未死的己方 token，自身不可作为扶起目标（自己倒地时无法行动）。

#### 10.6.5 治疗苏醒

任意治疗法术（如治愈术）命中倒地未死的己方，自动苏醒回对应 HP（不是 1 HP），重置 deathSaves。同样设置 `justRevived` 限制（仅当被治疗者正在当前回合行动时）。

#### 10.6.6 敌人智能补刀（BG3 风格）

替代旧版"玩家倒地 → 敌人原地待命不打"行为：

| 场景 | 行为 |
|---|---|
| 玩家活着 | 移动 + 攻击（原逻辑） |
| 玩家倒地但**有其他活威胁**（活且未倒地的 player/ally） | 敌人转去应对其他威胁，不打倒地玩家 |
| 玩家倒地且**无其他活威胁** | 敌人补刀倒地玩家，3 次失败即死 |

补刀伤害结算复用 `applyResult`：

- 近战命中倒地目标 = **自动暴击**（actions.js 中 `isUnconsciousMelee` 判定）→ 失败 +2
- 远程命中倒地目标 → 失败 +1
- 累计 3 次失败 → `dead=true` → `endCombat(false)`

#### 10.6.7 苏醒回合限制（justRevived）

| 苏醒路径 | 限制 |
|---|---|
| 自然 20 | `justRevived=true`；`action=0`；`moveLeft=0`；附赠动作保留 |
| 被扶起（help_downed） | 同上 |
| 被治疗 | 同上（仅当被治疗者在当前回合行动时） |

`trySpendCost` 检查 `justRevived` 标记，禁止动作类型；自由动作和附赠动作仍可用。`initTurnResources` 在下一回合开始时清除 `justRevived`。

#### 10.6.8 数据结构

```js
// token.data 上扩展的倒地相关字段
token.data.downed       // boolean，是否昏迷
token.data.dead         // boolean，是否死亡
token.data.deathSaves   // { successes, failures, stable }

// turnResources 上扩展的苏醒回合限制
turnResources.justRevived  // boolean，本回合只能用附赠动作
```

### 10.1 战斗地图内部数据流

```
combat-map.html 加载
    │
    ├─ 读取地图配置 data/combat/maps/<map_id>.json（障碍、出生点、scene）
    │
    ├─ 读取冒险章节数据（scene → npcs/items/quests → 左侧面板）
    │
    ├─ 读取角色卡 characters/elias.json → 重算攻击/AC → 玩家 token
    │
    ├─ 读取 npcs.json combat → 敌人 token（HP/AC/attacks）
    │
    ├─ 读取 spells.json → 法术查找表（动作面板 + 结算）
    │
    └─ 玩家交互
        ├─ 点动作按钮 → targeting → 点目标 → actions.js 结算
        ├─ 点「结束回合」→ 敌人 AI 回合 → 结算回玩家
        └─ 战斗结束 → 横幅 + 锁定操作
```

### 10.2 M6 嵌入冒险流程（v1.5）

```
adventure.html (玩家推进到 ch1-scene2)
    │ navigateToScene('ch1-scene2')
    │ 检查 scene.events 中是否有 type:'combat' 且有 map_id 的 encounter
    │ → 命中 'goblin-ambush'
    ▼
triggerCombatEncounter(encounterId, returnSceneId)
    │ 构建 encounterContext = {
    │   encounterId, encounterName, mapId, enemies: [...],
    │   playerSnapshot: { charId, hpCur, hpMax, ac },
    │   returnSceneId, nextSceneId, loot: [...], clues: [...]
    │ }
    │ 写入 sessionStorage.encounterContext
    ▼
window.location = 'combat-map.html?encounter=goblin-ambush'
    │
    ▼
combat-map.html / initMap()
    │ 读 URL ?encounter=xxx
    │ 从 sessionStorage 取 encounterContext
    │ 用 context.mapId 加载地图（triboar-trail-ambush.json）
    │ 用 context.enemies 渲染敌人 token
    │ 用 context.playerSnapshot 初始化玩家 HP/AC
    │ 战斗...
    ▼
endCombat(won)
    │ 构建 combatResult = {
    │   encounterId, encounterName, outcome: 'victory' | 'defeat',
    │   playerEndHp, loot, clues, nextSceneId
    │ }
    │ 写入 sessionStorage.combatResult
    │ 2.5 秒延迟（让玩家看清横幅）
    ▼
window.location = 'adventure.html?combat_result=goblin-ambush'
    │
    ▼
adventure.html / initGame() → consumeCombatResult()
    │ 读 URL ?combat_result=xxx
    │ 从 sessionStorage 取 combatResult
    │ 胜利：
    │   - 回写 state.character.combat.hp = playerEndHp / max
    │   - 战利品 push 到 state.character.inventory.items
    │   - 追加叙事日志："⚔ 你击败了 X。获得战利品：Y。线索：Z。"
    │   - 跳转 nextSceneId（ch1-scene3）
    │ 失败：
    │   - 追加 "☠ 你在战斗中倒下了，冒险就此结束。"
    │   - state.gameOver = true（阻塞后续操作）
    ▼
清理 URL 参数（history.replaceState）
```

## 13. 设计决策记录

| 决策 | 原因 |
|------|------|
| 圆 + 方格不冲突，圆只筛选格子 | 圆是"判定圈"，格是"落脚点"，token 永远吸附格中心 |
| 四方向扩散，墙后格子天然不可达 | 水波在墙边断开，源头杜绝"看着近走不过去" |
| 结算引擎放前端本地（actions.js） | 战斗地图不依赖 AI GM；后端只在持久化/AI 叙事时才介入 |
| 普攻/法术/敌人 AI 复用同一 resolveAttack | 一套骰子规则，玩家与敌人对等，无需两套逻辑 |
| 法术射程 18 米 → 9 米 | BG3 原版 18 米 = 12 格，覆盖 18×24 图大半；9 米（6 格）比例协调 |
| 战士配火焰箭戏法（1d10）而非火球术（8d6） | elias 是 4 级战士，火球术是法师 3 环 AoE，战士不该有；火焰箭符合"战士魔法攻击"定位 |
| 跳跃距离 = 力量值/5（round） | D&D 5e 远跳规则（力量17 → 3 格），不超 RAW 上限 |
| 跳跃无视路径障碍，只校验落点 | 跳越墙/树是跳跃的核心价值；高度判定留到 M7 |
| 跳跃期间 token 置 pointer-events:none | token 命中区 48px 会吞掉落点点击（玩家在 (9,12) 点 (9,10) 被当成点自己） |
| 真掷先攻（d20+敏捷） | 符合 D&D 规则；地精(+2) 略优，开场有紧张感 |
| 动作经济完整 5e（1动作+1附赠+移动力） | 对齐 BG3 / RAW；玩家与敌人对等，避免无限攻击 |
| 移动力按米展示，内部按格（√2）计算 | 斜走 √2 格非整数，按格显示会失真；米与角色卡/BG3 一致 |
| 移动力可拆分（移动→攻击→再移动） | 5e RAW：移动力可在动作前后拆分，战术性最强 |
| 资源条仅玩家回合显示 | 敌人回合玩家无操作权，隐藏资源条避免视觉干扰 |
| 按钮类型角标 + 预算耗尽置灰 | spells.json 已有 action_type 字段，复用数据驱动 UI |
| 「附加攻击」按钮删除，改 5 级被动 | RAW：Extra Attack 是 5 级被动特性，攻击动作自动结算 2 次，无需按钮 |
| 「斗气如潮」改为「动作如潮」（Action Surge） | 原 homebrew（附赠+1d8伤害）非 RAW；改为战士 2 级特性：自由动作，本回合获得 1 个额外动作，每短休 1 次 |
| 回气每战斗 1 次（secondWindUsed） | RAW：每短休 1 次；战斗内限 1 次简化，短休恢复留 M8 |
| 先攻升级 RAW 逐个掷骰（v1.2） | 旧版群体取最高信息量不足；RAW 每个生物单独 d20+敏捷，形成完整 initiative order，玩家能预判"下一个该谁" |
| 回合顺序头像条放地图上方（v1.2） | BG3 式横向条，不挤三栏；当前发光 + 下一个半亮，视线自然落在地图上方 |
| 同值先攻玩家优先 | D&D 5e 同值惯例：先攻加值高者先；简化为玩家优先，避免额外判定 |
