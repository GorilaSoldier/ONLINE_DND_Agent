## 1. 目标

将 `adventure.html` 从现有的 **7×7 网格地图导航模式** 重构为 **AI/真人 GM 叙事流模式**。

重构后的页面核心体验：

> 中央显示叙事日志 + 输入框，玩家输入动作后，由 AI GM 理解意图，规则引擎执行检定与状态变更，AI GM 再生成叙事回复。

本次实施将接入 **DeepSeek-V4-Flash** 作为 AI GM，替代规则引擎的模板化回复。规则引擎保留意图执行、检定掷骰、状态变更等确定性逻辑；AI 只负责理解玩家输入和生成叙事。

本次实施聚焦第一章，不实现真人 GM 面板、存档持久化、多人联机。流式输出（SSE）作为可选优化，先以非流式实现跑通流程，后续按需补充。

### 4.5 后端处理示例

以下示例展示规则引擎如何处理偷窃和移动。接入 AI 后，意图由 AI GM 解析并提供，规则引擎只负责执行：

```js
function mockGmProcess(playerText) {
  const lower = playerText.toLowerCase();

  // 1. 意图识别
  let intent = 'other';
  let target = null;

  if (lower.includes('侦察') || lower.includes('看看周围') || lower.includes('观察')) {
    intent = 'perception_check';
  } else if (lower.includes('调查') || lower.includes('检查') || lower.includes('仔细')) {
    intent = 'investigation_check';
  } else if (lower.includes('偷') || lower.includes('拿走') || lower.includes('顺走')) {
    intent = 'steal';
    target = extractTarget(lower, state.data.items);
  } else if (lower.includes('移动') || lower.includes('去') || lower.includes('走')) {
    intent = 'move';
    target = extractTarget(lower, state.data.locations);
  } else if (lower.includes('交谈') || lower.includes('说') || lower.includes('问')) {
    intent = 'talk';
    target = extractTarget(lower, state.data.npcs);
  }

  // 2. 根据意图生成回复
  switch (intent) {
    case 'perception_check':
      return handlePerceptionCheck();
    case 'investigation_check':
      return handleInvestigationCheck();
    case 'steal':
      return handleSteal(target);
    case 'move':
      return handleMove(target);
    case 'talk':
      return handleTalk(target);
    default:
      return { text: 'GM：（Mock）我理解了你的意图，但当前Mock阶段只能处理侦察、调查、偷窃、移动、交谈。' };
  }
}
```

### 4.6 偷窃处理示例

```js
function handleSteal(itemId) {
  const item = state.data.items[itemId];
  if (!item || !item.stealable) {
    return { text: `这里没有可以偷走的 ${itemId}。` };
  }

  // Mock 掷骰
  const roll = rollDice('1d20+0');
  const dc = item.difficulty || 10;

  if (roll.total >= dc) {
    // 成功：物品加入背包，地点中移除
    state.playerInventory.push(itemId);
    removeItemFromLocation(itemId);
    return {
      text: `你成功偷走了 ${item.name}，没有引起注意。`,
      stateChanges: [{ type: 'item_move', item: itemId, to: 'player' }]
    };
  } else {
    return {
      text: `你试图偷走 ${item.name}，但手一滑没拿稳。`,
      check: { roll, dc, success: false }
    };
  }
}
```

### 4.7 移动处理示例

```js
function handleMove(targetId) {
  const location = state.data.locations[targetId];
  if (!location) {
    return { text: '你无法到达那个地方。' };
  }

  state.currentLocationId = targetId;

  // 进入新地点时触发被动察觉
  const passiveFindings = checkPassivePerception(location);

  let text = location.scene_text;
  if (passiveFindings.length > 0) {
    text += '\n\n' + passiveFindings.map(f => f.description).join('\n');
  }

  return { text, stateChanges: [{ type: 'move', to: targetId }] };
}
```

## 7. AI GM 架构设计

### 7.1 模型选择：DeepSeek-V4-Flash

- **模型**：`deepseek-v4-flash`
- **API 端点**：`https://api.deepseek.com/v1`
- **接口协议**：兼容 OpenAI ChatCompletions
- **总参数**：284B，激活参数 13B
- **上下文**：1M tokens
- **价格**：输入 1 元/百万 tokens，输出 2 元/百万 tokens
- **Function Calling**：支持
- **结构化输出（JSON 模式）**：不支持
- **特点**：推理速度快、延迟低、成本低，适合高并发意图解析和叙事生成

### 7.2 职责划分

| 组件 | 职责 | 是否直接修改状态 |
|------|------|------------------|
| AI GM（interpret） | 理解玩家输入，输出意图、目标、建议检定 | 否 |
| 规则引擎 | 校验目标、执行检定、生成状态变更 | 否（生成变更建议） |
| 状态变更系统 | 执行状态变更（修改内存中的 game state） | 是 |
| AI GM（narrate） | 根据执行结果生成自然语言叙事 | 否 |

AI 不直接修改 JSON 或数据库，只输出建议；状态修改由确定性的规则引擎和统一状态变更系统完成。

### 7.3 整体调用流程

```python
# 1. AI 解析意图
intent_result = ai_gm.interpret(player_input, context)

# 2. 规则引擎执行
rule_result, changes = rule_engine.execute(intent_result, state)

# 3. 状态变更系统应用变更
apply_state_changes(changes, state)

# 4. AI 生成叙事
gm_text = ai_gm.narrate(player_input, intent_result, rule_result, changes, context)

# 5. 返回前端
return {
    "gm_text": gm_text,
    "intent": intent_result.intent,
    "checks": rule_result.checks,
    "state_changes": changes,
    "updates": build_client_updates(state)
}
```

### 7.4 AI 意图解析（Function Calling）

```json

  "parameters": {
    "type": "object",
    "properties": {
      "intent": {
        "type": "string",

          "investigation",
          "steal",
          "look",
          "use_item",
          "combat",

      "target_id": { "type": "string" },
      "target_type": {
        "type": "string",
```

### 7.5 Prompt 设计

#### System Prompt（意图解析）

```
你是 DNDBOX 的意图解析器，负责把玩家的自然语言输入解析为结构化动作。

规则：
1. 只能基于提供的当前场景、地点、NPC、物品进行解析。
2. 禁止推断未在上下文中出现的 NPC、地点或物品。
3. 如果玩家输入含糊不清，选择最可能的意图；如果完全无法理解，intent 使用 "other"。
4. 不要代替玩家做决定，只解析其输入表达的意思。
5. 输出必须通过调用 interpret_player_action 函数完成。
```

#### System Prompt（叙事生成）

```
你是 DNDBOX 的地下城主（GM），正在为玩家主持《凡戴尔的失落矿坑》第一章"地精之箭"。

你的职责：
1. 根据提供的当前场景、地点、NPC 状态、玩家动作、检定结果和状态变化，生成自然、有氛围的叙事回复。
2. 严格基于提供的上下文，禁止引入未提及的 NPC、地点、物品或剧情。
3. 如果玩家试图做上下文之外的事，委婉引导他们回到当前场景。
4. 保持叙事简洁，通常 2-4 句话为宜，不要过度描写。
5. 不要直接暴露 NPC 的内部状态，而是通过行为和表情暗示。
6. 不要代替玩家做决定，不要替玩家行动。
7. 输出纯文本，不要 Markdown、不要 JSON。
```

### 7.6 上下文管理

每次请求携带：

1. **章节摘要**：`chapters/ch1/summary.md` 内容
2. **当前场景**：场景名、地点描述
3. **在场 NPC**：名称、种族、身份、当前状态
4. **可见物品**：名称、描述、主人
5. **最近 8-12 轮对话**：保持叙事连续性
6. **玩家角色卡关键信息**：名称、种族、职业、等级、主要属性

不携带：
- 其他章节内容
- 隐藏信息（除非已发现）
- NPC 秘密
- 派系完整资料

### 7.8 延迟问题与优化

#### 当前预估延迟

| 步骤 | 耗时 |
|------|------|
| AI 解析意图 | 300ms ~ 1.5s |
| 规则引擎执行 | 10ms ~ 100ms |
| AI 生成叙事 | 500ms ~ 3s |
| 网络往返 | 100ms ~ 500ms |
| **总计** | **约 1s ~ 5s** |

#### 优化策略

1. **流式输出（SSE）**：AI 生成叙事时流式返回，减少感知延迟。本次先不做，后续补充。
2. **简单动作跳过 AI 叙事**：`查看周围`、纯检定类动作可由规则引擎直接返回固定模板。
3. **异步 + 加载动画**：前端显示"GM 正在思考..."，缓解等待焦虑。
4. **缓存意图解析**：相同输入可缓存解析结果。

本次先以**非流式实现**跑通全流程，验证效果后再决定是否上流式。

## 9. AI GM 当前支持范围

第一章实现阶段，AI GM 支持以下意图解析和叙事生成：

| 意图 | 示例输入 | 规则引擎处理 |
|------|----------|--------------|
| talk | "我和修达交谈" / "我威胁那个地精" | 目标 NPC 存在则返回招呼语或根据态度生成反应 |
| move | "我去洞穴入口" / "我走向后门" | 同场景内地点切换 |
| advance_scene | "我们出发去凡达林" / "追踪地精足迹" | 推进到下一幕 |
| perception | "我侦察周围" / "看看这里有什么" | 感知检定，揭示隐藏信息 |
| investigation | "我仔细检查" / "调查地面" | 调查检定，揭示隐藏信息 |
| steal | "我偷走钥匙串" / "顺走地图" | 巧手检定，成功则移动物品到玩家背包 |
| look | "查看周围" / "这是哪里" | 返回当前地点描述 |
| other | 任意未识别输入 | AI 直接生成回复，不触发规则引擎状态变化 |

本次不实现：
- 战斗相关意图（战斗将切换专门战斗模式）
- NPC 延迟反应与事件队列
- 被动技能自动触发
- 多玩家同步
- 流式输出

AI 的 `other` 意图用于处理闲聊、模糊动作等，由 AI 自由回复，但受上下文硬约束。
