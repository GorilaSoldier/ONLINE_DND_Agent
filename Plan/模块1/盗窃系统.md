# 盗窃系统（方案）

## 1. 目标

重构偷窃系统为四情况决策树 + 卫兵流程 + 通缉，覆盖"偷窃的每一种结果"，全部由规则引擎/盗窃引擎确定性执行，AI 基于真实结果叙事。

## 2. 新增：盗窃引擎

应新增独立引擎模块（如 `services/steal_engine.py`），专门处理偷窃全流程：

- **职责**：潜行前置 → 巧手 → 四情况分档 → 对峙选项 → 挣脱/逃脱 → 卫兵流程 → 通缉标记
- **与规则引擎关系**：盗窃引擎负责偷窃相关的确定性结算；AI 通过工具调用（intent）触发，基于引擎返回结果叙事
- **状态维护**：suspicion（三档）、被抓住状态（含挣脱次数）、arrest（卫兵 1d4 轮）、wanted_location（通缉）

## 3. 判定

```
玩家输入"偷X"
  → ① 潜行判定（未处于隐匿状态时）：隐匿 vs 在场目击者最高被动感知 + 警觉
       失败 → 目标警觉 +1，未得手、不质问（按兵不动）
       成功 → 继续
  → ② 巧手检定 vs DC = 目标被动感知 + 目标警觉
       └─ 失败 → 【情况一】没偷到被抓
       └─ 成功 → 得手，按 margin 分档：
             ├─ margin < 3           → 【情况二】刚偷到被当场瞥见（人赃并获）
             ├─ 3 ≤ margin ≤ 6       → 【情况四】延迟发现（5 秒反应期）
             └─ margin > 6           → 【情况三】无事发生
```

- 潜行/巧手判定沿用现有机制（DC 来源为观察者被动感知，子区域 sub 目击者判定等）

## 4. 四情况

### 情况一：没偷到被抓（巧手失败）

- 触发：巧手检定失败
- 后果：警觉 +2、转敌对、NPC 生气骂人
- **不进入对峙**，走不走玩家自决 → 结束

### 情况二：刚偷到被抓（巧手成功 & margin < 3）→ 人赃并获，立即对峙（flagrante）

选项：

1. **社交**：
   - 欺骗（DC 大幅提高）
   - 威吓（DC 受 NPC 胆子 + 职业影响）
   - 说服（删去，当场抓现行无效）
2. **赔偿 ×2**（只赔金额，物品不返还）→ 结束
3. **逃跑（挣脱：运动/体操自动取最高，vs 商人力量）**：
   - 挣脱成功 → 播报挣脱成功 → GM 提示可敏捷判定逃脱（vs 商人敏捷）
     - 成功 → 随机传送相邻出口 + 当前区域通缉 → 结束
     - 失败 → 商人叫卫兵 →【卫兵流程】（卫兵来前仍可社交 / 赔偿 / 同意搜身 / 挣脱）
   - 挣脱失败 → 进入【被抓住状态】（第 1 次挣脱用完）→ 商人叫卫兵 →【卫兵流程】

### 情况三：偷了无事发生（巧手成功 & margin > 6）

- 得手且无人知晓 → 结束

### 情况四：偷了延迟发现（巧手成功 & 3 ≤ margin ≤ 6）

- **5 秒固定反应期**：5s 内离开 = 无事（不触发通缉）；超时仍原地 → 商人对峙（discovered）
- 对峙选项：
  1. **同意搜身**：搜出 ×2 / 没搜出放行
  2. **给钱承认** ×2
  3. **社交**（欺瞒 / 威吓 / 游说，DC = 12 + 警觉）：
     - 成功 → 放行
     - 失败 → GM 播报 + 告知"NPC 即将对【角色名】强制搜身" → 玩家仍可选：
       - 接受搜身 → 搜出 ×3
       - 逃跑（未抓住）：敏捷 vs 商人敏捷 → 成功 = 逃脱[+通缉] / 失败 = 被抓 → 叫卫兵
  4. **拒绝** → 叫卫兵 →【卫兵流程】
- 对峙阶段**无挣脱**——只有被抓住状态才有

## 5. 卫兵流程（统一，情况二/四汇入）

- **触发**：情况二挣脱失败 / 情况二挣脱成功但敏捷判定失败 / 情况四拒绝 / 情况四社交失败后逃跑失败
- **到场时间**：`1d4` 轮赶来，GM 每轮播报"卫兵正在过来 / 卫兵越来越近了 / 卫兵就到门口了"

**赶来中**：

- 谈判赔偿（同意搜身）×3 / 社交（难度↑）→ 成功结束（卫兵到场后商人告知已私了 → 卫兵离开）
- 逃跑（敏捷 vs 商人敏捷）：成功 → 逃脱[+通缉] / 失败 → 被抓
- 若来自情况二（被抓住状态）：可挣脱（第 2 次机会，更难）

**卫兵到场** →【默认被抓住状态】→ 要求搜身：

- 仍 1 次社交（高难度）→ 成功化解；若失败，GM 会告知卫兵即将强制搜查（此时玩家仍可输入，进入下面的挣脱）
- 主动同意搜 → ×3
- 挣脱（vs 卫兵 DC12）：
  - 成功 → 敏捷判定逃脱（vs 卫兵敏捷）→ 成功 = 随机传送 + 通缉 / 失败 = 被按死
  - 失败 → 被按死
- 被按死 → ×3 赔偿 + 进监狱（关押一夜自动释放）【仅卫兵有送监狱资格】

**被抓住期间总共 2 次挣脱机会**，第 2 次失败 → 再也不能挣脱

## 6. 通缉（wanted）

- **在 NPC 面前逃跑成功 → 当前区域通缉**（情况二挣脱成功、情况四社交失败后逃跑成功、卫兵赶来中逃跑成功等）
- **情况四 5 秒反应期内离开 = 无后续**（不触发通缉）
- `wanted_location`：仅当前区域生效，其他场景不受影响
- 本次实现：只做标记 + GM 播报"你在这片区域被通缉了"

## 7. GM 交互规则

- GM 可**适度提醒**玩家此时可进行什么操作
- 若玩家专门询问，可**详细告知**；在卫兵赶来的过程中，玩家询问 GM 该如何操作的对话，**不算做一轮耗时**（不消耗卫兵到场轮数）
- 不应**强制规定**玩家此时该做什么
- 玩家操作出现偏差，可进行提醒（同样**不算做一轮耗时**）

## 8. 状态

- `player_stealth`：隐匿状态
- `npc_alerts`：NPC 警觉（巧手失败 +2 / 成功 +1 / 潜行失败 +1）
- `hostile_npcs`：敌对 NPC 集合（交易涨价）
- `suspicion`：被怀疑状态，mode 三档——`caught_attempted`（情况一，不进入对峙）/ `flagrante`（情况二，人赃并获）/ `discovered`（情况四，延迟发现 + detected_at）
- `caught`（被抓住状态）：含挣脱次数（共 2 次），仅此状态可挣脱
- `arrest`：卫兵逮捕状态机（summoned 赶来中 1d4 轮 → arrived 到场 → ...；含卫兵剩余到场轮数）
- `wanted_location`：通缉区域（仅当前区域，本次只标记）
